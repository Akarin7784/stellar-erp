## 4. バッチ詳細

### 4.1 BAT-PUR-001 交期跟踪・催货提醒

| 項目 | 内容 |
|---|---|
| バッチ ID | BAT-PUR-001 |
| バッチ名 | 交期跟踪・催货提醒 |
| 実行方式 | 日次（毎日 07:00、Asia/Shanghai） |
| 想定処理時間 | 3 分（未入荷 1,000 行想定） |
| 対象データ | `pur_purchase_order_line` WHERE `line_status IN (30,35)` AND `line_status ≠ 40` AND `remain_qty > 0` |
| 冪等性 | 再実行可（通知は当日分を再送しない設定可） |
| 排他 | `pg_advisory_lock('BAT_PUR_001')` |
| 失敗時 | リトライ 3 回（5 分間隔）→ 失敗で運用担当へメール |
| 関連機能 | F-PUR-023 |

**処理手順**

1. 起動条件チェック：当日未実行または手動実行であること。会計期間状態は参照のみ（業務停止しない）。
2. 未入荷 PO 明細を抽出し、基準日 = `supplier_promised_date` ?? `delivery_date`、遅延日数・区分（正常/臨期/遅延/厳重遅延/超期未入荷）を計算する。
3. 購買担当別・供應商別に集約し、遅延・厳重遅延・超期未入荷の明細を通知対象とする。
4. 站内通知（購買担当・購買经理）＋設定によりメールを送信する。`pur_delivery_followup` の `next_followup_date = 当日` の明細もリマインド対象に含める。
5. 通知結果（件数・失敗件数）をジョブログに記録する。通知失敗は業務データをロールバックしない（非同期・再送）。

**入出力**

| 種別 | 対象 | 内容 |
|---|---|---|
| 入力 | `pur_purchase_order(_line)`、`pur_delivery_followup` | 未入荷・基準日・催货状況 |
| 出力 | SYS 通知、ジョブログ | 通知一覧・件数 |

**異常処理**

| 異常 | 検知 | 処理 | 通知 | 再実行 |
|---|---|---|---|---|
| 対象 0 件 | 抽出結果 | 正常終了（ログのみ） | なし | 可 |
| 通知送信失敗 | 通知サービス | リトライ、失敗件数を記録 | 運用担当 | 可（当日分再送設定時） |
| DB 接続エラー | ジョブ基盤 | 中断 | システム管理者 | 可 |

### 4.2 BAT-PUR-002 超期未入荷 PO 抽出・关闭候補

**処理手順**：①未入荷かつ遅延 30 日超の PO 明細を抽出 ②供應商・購買担当別に集約し取消候補リストを生成 ③購買经理・購買担当へ通知 ④リストは SCR-PUR-025（フィルタ「超期未入荷」）から参照可能。出力：取消候補一覧（PDF は PRT-PUR-007 を利用）。異常：抽出 0 件は正常終了。

### 4.3 BAT-PUR-003 入荷済未請求（暫估）照合

| 項目 | 内容 |
|---|---|
| バッチ ID | BAT-PUR-003 |
| 実行方式 | 日次（06:00）＋月結前（手動起動可） |
| 対象データ | 入荷確定済（`receipt_status ∈ {30,35,40}`）で `invoiced_qty < accepted_qty + concession_qty − returned_qty` の GR 明細 |
| 冪等性 | 再実行可（スナップショットは当日分を置換） |
| 関連機能 | F-PUR-020 |

**処理手順**

1. 対象 GR 明細を抽出し、未請求残数量 × PO 税抜単価 = 暫估残高を計算する（CALC-11）。
2. 前日比・滞留日数（入荷日からの経過日数）を付与し、滞留 30 日超・60 日超を区分する。
3. FIN の暫估残高（同期参照または当日の FIN 側暫估台帳）と比較し、差異があれば `MSG-PUR-110` の警告リストを生成する（月結時は差異 0 が条件、09 §10.3 #3）。
4. PRT-PUR-011 出力用のデータを保存（またはビュー再計算）し、購買经理・財務へ結果通知（差異あり時のみ）。
5. 月結前実行時は「暫估残高・滞留件数」を月結チェック結果として記録する。

**入出力**：入力 `pur_receipt_line`／`pur_purchase_order_line`／`pur_invoice_match`／FIN 暫估参照。出力：暫估台帳データ、差異リスト、ジョブログ。

### 4.4 BAT-PUR-004 三单匹配差异滞留監視

**処理手順**：①`pur_invoice_match.match_status ∈ {3（超容差）, 6（保留）}` および `pur_invoice.matched_status ∈ {4,6}` を抽出 ②滞留日数（登録日からの経過）を計算 ③7 日超・14 日超・30 日超を区分し、購買担当・財務へ通知 ④保留（HOLD）は「未入荷待ち」「PO 未紐付」の理由別に集約。異常：FIN 側計上との不整合（E17 未処理）は `MSG-PUR-110` でアラート。

### 4.5 BAT-PUR-005 请购未转单提醒

**処理手順**：①状態 25（承認済）かつ `converted_qty = 0`、承認日から 3 営業日超の PR を抽出 ②購買担当へ通知 ③状態 35（一部転単）で残量あり・7 日超も対象。出力：リマインド一覧。異常：抽出 0 件は正常終了。

### 4.6 BAT-PUR-006 供应商绩效月次计算

| 項目 | 内容 |
|---|---|
| バッチ ID | BAT-PUR-006 |
| 実行方式 | 月次（毎月 1 日 02:00） |
| 想定処理時間 | 10 分（供應商 800 社） |
| 対象データ | 前月に取引（発注/入荷/検査/報価）がある供應商 |
| 冪等性 | 条件付き：`(period_code, supplier_id)` で UPSERT。確定後（`confirmed_at` 非 NULL）の再計算は上書きせず警告 |
| 関連機能 | F-PUR-026 |

**処理手順**

1. 対象期間・供應商を抽出する（前月の `pur_purchase_order_line`、`pur_receipt_line`、`pur_supplier_quotation`）。
2. 交付：入荷行数・按期行数 → 交付達成率（CALC-02）。
3. 数量：発注数量・入荷数量 → 数量達成率（CALC-03、上限 100）。
4. 質量：受入数量・合格数量 → 質量合格率（CALC-04）、退貨率（CALC-05）。
5. 価格：數量加重平均単価と同類物料平均 → 価格競争力（CALC-06）。
6. 響応：RFQ 發出から報価までの平均日数 → 響応速度（CALC-07）。
7. 総合評分・等級を計算（CALC-08）し、`pur_supplier_performance` に UPSERT する。データ不足指標は基準点補完＋`insufficient_data=true`。
8. 購買经理へ確認通知（SCR-PUR-028 で確認・確定）。

**異常処理**：対象供應商 0 件は正常終了。計算途中の例外はロールバックし、翌日手動再実行を可能とする（部分更新しない）。

### 4.7 BAT-PUR-007 采购价格异常检查

**処理手順**：①前日に承認された PO 明細（`po_status ≥ 25`、`approved_at` が前日）を抽出 ②基準単価（同供應商・同物料の直近 3 か月加重平均、なければ最終成交价）を計算 ③異常率（CALC-11）が ±10% 超の行を警告リスト化 ④購買经理へ通知（站内）。出力：警告一覧（SCR-PUR-026 の異常タブ）。冪等：同日分を置換。

### 4.8 BAT-PUR-008 询价报价締切処理

**処理手順**：①`rfq_status IN (30,35)` かつ `quote_deadline <= now()` の RFQ を抽出 ②状態を 35（報価収集）に遷移 ③未回答供應商（`response_status=1`）を 4（期限切れ）に更新 ④購買員へ「締切・未回答者一覧」を通知。異常：状態遷移競合（同時操作）はスキップしログ記録。

### 4.9 BAT-PUR-009 采购报表日次集計

**処理手順**：①前日までの PO/GR/PIV/PRT 実績を抽出 ②期間・工廠・部門・供應商・物料分類別に採購額（発注/入荷/請求の 3 口径）・未入荷残・価格適用率・集中度を集計 ③集計テーブル（RPT 域または PUR 集計ビュー）へ保存 ④差異検出（GR 合計 ≠ PO 累計等）は `MSG-PUR-125` でアラート。冪等：全件再計算で置換。実行時間 20 分以内。

### 4.10 BAT-PUR-010 长期未照合发票提醒

**処理手順**：①`matched_status ∈ {0,1,6}` または `ap_status=0` かつ `registration_date` から 30 日超の PIV を抽出 ②30/60/90 日区分で財務・購買へ通知 ③60 日超は財務经理確認対象としてリスト化。異常：なし。

### 4.11 BAT-PUR-011 発注未送信・承認滞留チェック

**処理手順**：①状態 25 かつ `sent_at IS NULL` で承認から 1 営業日超の PO ②状態 20 で提出から 48 時間超の PO ③それぞれ購買担当・購買经理・上位者へ通知（エスカレーション、08 §8.2）。出力：滞留一覧。冪等：再実行可。
