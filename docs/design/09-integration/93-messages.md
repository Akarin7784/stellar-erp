## 1. 採番・記述規則

| 項目 | 規則 |
|---|---|
| ID | `MSG-INT-{3桁}`。001〜099。欠番再利用禁止 |
| 種別 | `E`（処理中断）、`W`（警告・続行可）、`I`（情報・成功）、`C`（確認） |
| 本文 | 中国語。**何が起きたか + どうすればよいか**を利用者視点で書く。例外名・スタックトレース・secret・口座番号を含めない |
| プレースホルダ | `{0}`、`{1}`… の順。件数・番号・理由を入れる |
| API コード | [91 §4](91-api-design.md) の INT 領域コード（90000〜90999）と対応させる |
| 共通メッセージ | 入力・権限・排他・期間などは [MSG-COM-xxx](../00-common/05-common-message-list.md) を優先し、本表では再定義しない |

### 1.1 種別ごとの表示方法

| 種別 | 画面表示 | API | ログ |
|---|---|---|---|
| E | ダイアログ＋項目エラー | 4xx/5xx + `code` | WARN/ERROR |
| W | トースト（橙）または確認 | 200 + `code`（警告） | WARN |
| I | トースト（緑） | 200 + `code=0` | INFO |
| C | 確認ダイアログ（OK/キャンセル） | — | INFO |

## 4. 共通メッセージの使用指針

| 事象 | 使用する共通メッセージ |
|---|---|
| 必須・桁・範囲・相関チェック | `MSG-COM-040`〜`049` |
| 権限なし | `MSG-COM-030`、`MSG-COM-031` |
| 楽観排他・処理中 | `MSG-COM-033`、`MSG-COM-035` |
| 状態不整合 | `MSG-COM-034` |
| 期間締切 | `MSG-COM-071` |
| ファイルサイズ・形式 | `MSG-COM-060`〜`062` |
| システムエラー | `MSG-COM-080` |
| レート制限（汎用） | `MSG-COM-082` |

> 本域固有の文面が必要な場合のみ `MSG-INT-xxx` を追加する。同一文面の重複定義を避ける。

## 5. プレースホルダ・変数一覧

| プレースホルダ | 意味 | 型・例 | 使用メッセージ |
|---|---|---|---|
| `{0}` | 汎用（エラー理由・件数・日数） | 文字列/数値 | 多数 |
| `{0}`（IF 系） | エラー詳細・HTTP ステータス | `timeout after 10000ms` | MSG-INT-003 |
| `{0}`（税系） | 税局拒否理由 | `购买方税号不一致` | MSG-INT-020 |
| `{0}`（銀体系） | 銀行応答コード/理由 | `ACCOUNT_MISMATCH` | MSG-INT-040 |
| `{0}`（ファイル系） | 行番号 | `128` | MSG-INT-050/055/056 |
| `{0}`（再送系） | 待機時間 | `5 分钟` | MSG-INT-074 |
| `{0}`（通知系） | 再送回数 | `3` | MSG-INT-092 |
| `{1}` | 第 2 引数（項目名・金額・件数） | `invoiceNo` | MSG-INT-050 等 |

> プレースホルダは本文の出現順に `{0}`、`{1}` を割り当てる。同じ番号を 2 回使わない。ユーザ入力値をそのまま埋め込まず、必要に応じてマスキングする。

## 7. メッセージ本文の作成例

| 区分 | 例 | 判定 |
|---|---|---|
| 良い例 | 税局拒绝了开票请求（原因：购买方税号与登记信息不一致），请修正后重新发送。 | ○ 何が起きたか＋対処が明確 |
| 良い例 | 对账单文件格式不正确（第 128 行：金额列不是数字），已取消本次导入。 | ○ 位置と理由が明確 |
| 悪い例 | 系统错误。 | × 原因・対処がない |
| 悪い例 | NullPointerException at TaxService.java:88 | × 技術情報の露出 |
| 悪い例 | 开票失败，请重试。 | △ 再送しても解決しない場合がある（原因を示す） |
| 悪い例 | 请联系管理员。 | △ 何を確認すべきか不明（理由を添える） |

**原則**：

1. 1 メッセージに 1 原因。複数原因をまとめない。
2. 再送で解決するもの（通信・5xx）と、修正が必要なもの（4xx・業務拒否）を区別して書く。
3. 金額・口座・税号は必要最小限（下 4 桁・マスク）。
4. 「～と思われます」等の推測表現を使わない。確定した事実のみ書く。

## 8. メッセージとログ出力

| 種別 | アプリログ | 監査ログ | 備考 |
|---|---|---|---|
| E | WARN/ERROR（trace_id 付き） | 失敗の重要操作（開票・付款・取込） | secret・口座は出力しない |
| W | WARN | 原則なし | 再送・スキップ |
| I | INFO | 成功の重要操作 | — |
| C | INFO | なし | ユーザの選択結果を記録 |

> ログには `requestId`・`interfaceCode`・`bizKey` を含め、メッセージ本文はそのまま保存する（個人情報を含めない）。
