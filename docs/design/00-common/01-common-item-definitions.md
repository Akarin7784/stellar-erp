## 1. 適用範囲

全業務テーブル、全画面、全 API に共通する項目・値域・精度・表現を定義する。各業務域の設計書は本定義を**引用**し、同一項目（例：作成日時、金額、状態）について再定義してはならない。本定義と異なる設計が必要な場合は、理由を付けて Lead に申告し本定義を改訂する。

## 2. 共通カラム（必須監査項目）

### 2.1 カラム一覧

| # | 物理名 | 論理名 | 型 | NULL | 既定値 | 説明 |
|---|---|---|---|---|---|---|
| 1 | `id` | 主キー | `BIGINT` | NOT NULL | アプリ生成 | 雪花 ID（MyBatis-Plus `ASSIGN_ID`）。API・画面では文字列で表現 |
| 2 | `tenant_id` | 租户 ID | `BIGINT` | NOT NULL | `current_setting('app.tenant_id')::bigint` | 租户＝部署客户。RLS の隔離キー（ENABLE+FORCE、USING/WITH CHECK）。`DEFAULT 0` 禁止、上下文なしの INSERT は失敗。首期の租户上下文既定値は 0（アプリ側 `TenantContext`）。詳細は [10](10-rls-and-db-roles.md) |
| 3 | `company_id` | 公司 ID | `BIGINT` | NOT NULL | `1` | 会計主体・組織単位。Phase 2 で多公司対応 |
| 4 | `created_at` | 作成日時 | `TIMESTAMPTZ` | NOT NULL | `now()` | サーバ時刻（Asia/Shanghai 表現） |
| 5 | `created_by` | 作成者 ID | `BIGINT` | NOT NULL | `0` | システム処理は `0`。ユーザは `sys_user.id` |
| 6 | `updated_at` | 更新日時 | `TIMESTAMPTZ` | NOT NULL | `now()` | 更新の都度アプリ層で更新 |
| 7 | `updated_by` | 更新者 ID | `BIGINT` | NOT NULL | `0` | 同上 |
| 8 | `version` | 楽観排他版数 | `INT` | NOT NULL | `0` | 更新成功ごとに +1。詳細は第 11 章 |
| 9 | `deleted` | 論理削除 | `BOOLEAN` | NOT NULL | `FALSE` | マスタのみ使用可（取引データは取消ステータスで管理） |
| 10 | `remark` | 備考 | `VARCHAR(500)` | NULL | NULL | 利用者入力の自由記述。業務項目の代替にしない |
| 11 | `ext_data` | 拡張項目 | `JSONB` | NULL | NULL | 顧客カスタム項目。第 10 章 |

### 2.2 DDL 雛形

```sql
-- 全業務テーブル共通の監査カラム（実装時は各テーブル DDL に展開する）
id          BIGINT       NOT NULL,
tenant_id   BIGINT       NOT NULL DEFAULT 0,
company_id  BIGINT       NOT NULL DEFAULT 1,
created_at  TIMESTAMPTZ  NOT NULL DEFAULT now(),
created_by  BIGINT       NOT NULL DEFAULT 0,
updated_at  TIMESTAMPTZ  NOT NULL DEFAULT now(),
updated_by  BIGINT       NOT NULL DEFAULT 0,
version     INT          NOT NULL DEFAULT 0,
deleted     BOOLEAN      NOT NULL DEFAULT FALSE,
remark      VARCHAR(500),
ext_data    JSONB,
CONSTRAINT pk_{table} PRIMARY KEY (id)
```

### 2.3 共通カラムの付与ルール

| テーブル種別 | 必須カラム | 備考 |
|---|---|---|
| マスタ（MDM/SYS） | 全部（`deleted` 含む） | 論理削除可。削除前に参照チェック必須 |
| トランザクション（SAL/PUR/INV/PRD/FIN/WF/INT） | `id`〜`version`＋`remark`/`ext_data`（任意）。`deleted` は原則付けない | 取消・廃止はステータスで表現し、物理削除禁止 |
| 明細（`_line`/`_detail`） | 同上 | `id`、親 `{parent}_id`、行番号 `line_no` |
| 履歴・ログ（`_his`/`_log`） | `id`、`created_at`、`created_by`、`tenant_id` | 更新系カラム不要（追記専用） |
| コード/辞書 | `id`〜`version`、`deleted` | 使用停止は有効期間または `status` |

> `updated_at`/`updated_by` はアプリ層の MetaObjectHandler で自動充填する（DB トリガは使わない）。バッチ処理の更新もシステムユーザ ID を付与する。

## 5. 日付・時刻・期間

| 項目種別 | 型 | 形式 | 例 | 備考 |
|---|---|---|---|---|
| 業務日付（伝票日付・納期・入出庫日） | `DATE` | `YYYY-MM-DD` | `2026-10-20` | タイムゾーンなし。業務上の日付 |
| システム日時（作成・更新・承認・過帳） | `TIMESTAMPTZ` | `YYYY-MM-DD HH:MM:SS+08:00` | `2026-10-20 14:30:00+08:00` | DB 保存は UTC、表示は Asia/Shanghai |
| API の日時表現 | ISO 8601 | `yyyy-MM-dd'T'HH:mm:ssXXX` | `2026-10-20T14:30:00+08:00` | 文字列 |
| 時刻のみ（シフト開始等） | `TIME` | `HH:MM:SS` | `08:00:00` | — |
| 会計期間 | `VARCHAR(7)` | `YYYY-MM` | `2026-10` | `fin_period.period_code`。会計年度 = 1〜12 月（中国） |
| 年度 | `SMALLINT`（`fiscal_year`） | `YYYY` | `2026` | — |
| 工数・作業時間 | `NUMERIC(12,2)` | 時間（h） | `0.75` | 分は小数 2 桁まで |

- 「今日」の判定はサーバ時刻（Asia/Shanghai）を基準とする。クライアント時刻を信頼しない。
- 日付範囲チェックは両端含む（`from <= value <= to`）。納期の「過去日」許可/禁止は機能側で定義する。
- 会計期間の状態（未開始 / 進行中 / 締切済 / 年結済）は `fin_period.status` で管理し、締切済期間への登録・更新は業務エラーとする。

## 6. 金額・数量・単価・率の精度

### 6.1 精度一覧（全社統一）

| 項目 | 物理名例 | 型 | 小数桁 | 単位 | 用途 |
|---|---|---|---|---|---|
| 金額（合計・税額・残高） | `amount`、`tax_amount`、`balance_amount` | `NUMERIC(18,2)` | 2 | 元（CNY） | 帳票・会計の確定値 |
| 単価（販売・購買・標準） | `unit_price`、`standard_price` | `NUMERIC(18,6)` | 6 | 元/単位 | 端数保持のため 6 桁 |
| 数量 | `quantity`、`qty_on_hand` | `NUMERIC(18,4)` | 4 | 単位コードによる | 重量・長さ・個数 |
| 換算率（単位） | `conversion_rate` | `NUMERIC(18,8)` | 8 | 倍率 | 1 単位 = n 基本単位 |
| 為替レート | `exchange_rate` | `NUMERIC(18,8)` | 8 | 円/外貨等 | 間接Quote は分母として保持 |
| 税率 | `tax_rate` | `NUMERIC(7,4)` | 4 | % | `13.0000` = 13% |
| 比率・歩留り | `ratio` | `NUMERIC(7,4)` | 4 | — | `0.8750` = 87.5%（歩留り）または % 表現を項目定義で明記 |
| 原価（単位） | `unit_cost` | `NUMERIC(18,6)` | 6 | 元/単位 | 移動平均単価 |
| 原価（合計） | `total_cost` | `NUMERIC(18,2)` | 2 | 元 | 伝票・会計 |
| 工数（時間） | `work_hours` | `NUMERIC(12,2)` | 2 | 時間 | 報工・能カ |
| 重量 | `weight` | `NUMERIC(18,6)` | 6 | KGM | 物量 |
| 体積 | `volume` | `NUMERIC(18,6)` | 6 | MTQ | 物量 |

### 6.2 計算順序と端数処理（詳細は [08 共通业务规则](08-common-business-rules.md) 第 4 章）

1. 数量 × 単価 = **明細金額（丸め前）**。単価は 6 桁、数量は 4 桁で計算し、`NUMERIC` のまま保持。
2. 明細金額を **四捨五入（0.5 は切り上げ）で小数 2 桁**に丸める。
3. 税額 = 明細金額（税抜）× 税率。**明細単位で四捨五入**し、伝票合計は明細の合計（伝票全体で再丸めしない）。
4. 伝票合計 = Σ明細金額。合計行に「数量合計・金額合計・税額合計」を表示。
5. 端数が生じる値引・按分は、最終明細または指定明細に寄せ、寄せ先を画面・データに記録する（`rounding_target_line_no`）。
6. 為替換算が必要な場合は「外貨金額（原幣）→ レート乗算 → 元貨金額（2 桁丸め）」の順とし、レート・丸め前後の金額を保持する。

### 6.3 表示規則

| 種別 | 表示 | 例 |
|---|---|---|
| 金額 | 桁区切り + 小数 2 桁 + 通貨コード列 | `CNY 1,234,567.89` |
| 単価 | 桁区切り + 小数 2〜6 桁（項目定義で桁数指定） | `6.850000` または `1,234.56` |
| 数量 | 桁区切り + 小数 0〜4 桁（末尾 0 を省略可、編集時は単位精度に合わせる） | `1,200 PCE`、`2.5000 KGM` |
| 税率 | `%` 付き 2 桁 | `13.00%` |
| 空値 | `-` を表示（0 と区別） | `-` |
| マイナス | 赤色表示（一覧・帳票） | `-1,234.56` |

## 7. 状態・区分値の扱い

### 7.1 共通ステータス体系（伝票系）

| コード | 状態名 | 意味 | 許容される主な遷移先 |
|---|---|---|---|
| `10` | 草稿 | 登録済み・未提出。編集/削除可 | 20、90 |
| `20` | 承認待ち | ワークフロー審査中。編集は原則不可（差戻しで 10 へ） | 25、95、10（差戻し） |
| `25` | 承認済 | 承認完了・未実行 | 30、90 |
| `30` | 発行済／未実行 | 後続処理の実行待ち（例：未入荷の PO、未出荷の SO） | 35、40、90 |
| `35` | 一部実行 | 一部入荷・一部出荷など部分完了 | 35、40、90 |
| `40` | 完了／クローズ | 全数量完了。以後の変更は取消・返品処理のみ | （終端） |
| `90` | 取消 | 取消済み。関連在庫・会計は逆仕訳／戻し処理済みであること | （終端） |
| `95` | 却下 | 承認却下。再申請は新規伝票または 10 へ戻して修正 | 10（再申請） |

> 業務域固有の状態（例：`入荷待ち`、`検収中`、`支払済`）は上記コード体系を**拡張**して使用する。各域は `00-overview.md` に「共通ステータスとの対応表」を必ず示す。状態の意味が異なるコードを他域と共有しない。

### 7.2 区分値の持ち方（3 層方針）

| 種類 | 持ち方 | 例 |
|---|---|---|
| 処理ロジックが依存する固定区分 | Java enum + DB `SMALLINT`（コード表は設けない） | 伝票ステータス、入出庫方向、税区分 |
| 業務運用で追加・変更される区分 | マスタテーブル（`mdm_*` / `sys_dict_item`） | 物料分類、顧客分類、倉庫種別、支払条件 |
| 一時的な自由入力 | テキスト（`remark` 等）。区分値として使わない | 備考 |

固定区分は「区分値一覧表」を各文書に置き、値・意味・使用箇所を明記する。DB にはコード値（数値/文字列）のみ保存し、名称はマスタまたは message properties で解決する。

### 7.3 フラグ・真偽値

- DB は `BOOLEAN`（`is_xxx`、`xxx_flag`）。
- 画面は「はい/いいえ」「有効/無効」ラベル。API は `true/false`。
- 「未設定」を許す場合は NULL 可とし、画面に「未設定」を表示する。既定値で潰さない。

## 8. コード項目の扱い

| 項目 | 規則 |
|---|---|
| 項目構成 | コード（`*_code`）+ 名称（`*_name`）。画面・帳票は名称を表示し、API はコードを返す（必要に応じ名称も併記） |
| コード値 | 原則 `VARCHAR`、大文字英数字・ハイフン・アンダースコアのみ。全角・空白・小文字のみ禁止（外部システムコードを除く） |
| 有効期間 | `valid_from`/`valid_to`（DATE）。期間外のコードは新規選択不可、既存データの表示は可 |
| 使用停止 | マスタの `status=0`（無効）または `deleted=true`。使用中コードの物理削除禁止 |
| 参照整合 | コード項目の値は参照先マスタに存在すること（入力チェック「コード存在」）。削除済みコードへの新規参照は不可 |
| 多言語 | Phase 2 対応。名称は `name`（中文）を正とし、`name_en` 等は拡張項目または専用列で管理 |
| 標準コード | 通貨・単位・国・地域・税区分・勘定科目等は [06-code-list.md](06-code-list.md) の実データを使用する |

## 10. 拡張項目（JSONB `ext_data`）

顧客・物料などのカスタム属性は、列追加ではなく `ext_data JSONB` に保存する。

```json
{
  "customer_grade": "A",
  "tax_region": "JS",
  "delivery_window": "08:00-12:00",
  "custom_field_001": "2026-01-15"
}
```

- 項目定義は `mdm_ext_field`（適用対象、項目コード、項目名、型、必須、選択肢、検証式、表示順）で管理する。
- API は `ext_data` オブジェクトをそのまま入出力し、サーバ側で項目定義に基づく型・必須チェックを行う。
- 検索用に GIN インデックスを張る（`USING gin (ext_data jsonb_path_ops)`）。頻繁に検索・集計する項目は昇格して通常列にする。
- 拡張項目を業務ロジックの分岐条件に使う場合は、設計書にその依存を明記する（暗黙依存の禁止）。

## 11. 楽観排他・論理削除

### 11.1 楽観排他

- 画面で編集する全マスタ・伝票は `version` を保持し、UPDATE 時に `WHERE id = ? AND version = ?`、`SET version = version + 1`。
- 更新件数 0 の場合、`MSG-COM-005`「他のユーザが更新しました。最新情報を再取得してください」を返す（HTTP 409）。
- 一覧からの一括更新も対象ごとに version を検証する（全件成功 or 全件失敗のトランザクション）。
- 排他が必要な処理（在庫引当、採番、月結）は行ロック（`SELECT ... FOR UPDATE`）を併用し、設計書にロック対象・順序・待ち時間（例 3 秒）を明記する。

### 11.2 論理削除

- 対象：マスタのみ（`mdm_*`、`sys_*` の管理系）。伝票は取消ステータスで表現し、論理削除しない。
- 一意制約は論理削除を考慮し、部分一意インデックス `WHERE deleted = FALSE` を張る。

```sql
CREATE UNIQUE INDEX uk_mdm_material_company_code
  ON mdm_material (company_id, material_code)
  WHERE deleted = FALSE;
```

- 削除前チェック：参照中（未完了伝票・在庫残・BOM 使用等）のマスタは削除不可。`MSG-MDM-xxx` を返し、代替として「使用停止」を案内する。

## 12. 監査ログ項目（`sys_audit_log`）

| 項目 | 型 | 説明 |
|---|---|---|
| `id` | BIGINT | 主キー |
| `trace_id` | VARCHAR(64) | リクエスト追跡 ID（API ヘッダ `X-Request-Id`） |
| `user_id` | BIGINT | 操作者（未ログインは 0） |
| `username` | VARCHAR(64) | 操作者ログイン名（スナップショット） |
| `operation_type` | VARCHAR(32) | LOGIN / LOGOUT / CREATE / UPDATE / DELETE / SUBMIT / APPROVE / REJECT / EXPORT / IMPORT / PRINT / POST / REVERSE / CLOSE |
| `module` | VARCHAR(32) | モジュール名 |
| `resource` | VARCHAR(64) | リソース名 |
| `resource_id` | VARCHAR(64) | 対象 ID |
| `resource_no` | VARCHAR(64) | 対象業務番号 |
| `before_data` | JSONB | 変更前（マスタ・重要項目のみ。金額・ステータス必須） |
| `after_data` | JSONB | 変更後 |
| `ip_address` | VARCHAR(45) | IPv4/IPv6 |
| `user_agent` | VARCHAR(500) | UA |
| `result` | SMALLINT | 1=成功 / 0=失敗 |
| `error_message` | VARCHAR(1000) | 失敗理由 |
| `occurred_at` | TIMESTAMPTZ | 発生日時 |

- 記録対象：ログイン/ログアウト/失敗、全マスタ・伝票の登録/更新/削除、承認操作、エクスポート/インポート、印刷、過帳/取消/月結、権限・パラメータ変更。
- ログは追記専用。画面から更新・削除不可。保存期間は [08 共通业务规则](08-common-business-rules.md) 第 12 章。
- 個人情報・パスワード・銀行口座等は `before_data`/`after_data` に含めずマスキングする。

## 13. 帳票共通印字項目

| 区分 | 項目 | 説明 |
|---|---|---|
| ヘッダ | 会社名（中文+英文）、ロゴ、拠点名 | `sys_company`/`mdm_factory` から取得 |
| ヘッダ | 文書名、文書番号、発行日、版数（必要時） | 文書番号は採番規則に従う |
| ヘッダ | 取引先名・コード・住所・連絡先 | 伝票の取引先スナップショットを使用（マスタ変更の影響を受けない） |
| 明細 | 行番号、品目コード、品名、仕様、数量、単位、単価、金額、税率、税額 | 明細順は `line_no` |
| フッタ | 合計数量、小計、値引、税抜合計、税額、合計金額（大小文字併記）、備考 | 通貨コードを明記 |
| フッタ | 作成者、承認者、発行責任者、印欄（必要時）、ページ番号「n/N」、出力日時 | 承認者は承認履歴から |
| 共通 | 機密区分、配布先、問い合わせ先 | 機密区分は帳票ごとに定義 |

> 取引先名・住所・税率等は**伝票登録時点のスナップショット**を保持する（マスタ変更で過去帳票が変わらない）。スナップショット対象項目は各域の DB 設計書で明記する。

## 14. 画面共通項目・表示規則

### 14.1 項目種別

| 種別 | 画面部品 | API 型 | 備考 |
|---|---|---|---|
| テキスト | input | string | 最大桁数は項目定義 |
| 数値（金額/数量/単価） | input-number | decimal string | 桁数・精度は第 6 章 |
| 日付 | date-picker | string(yyyy-MM-dd) | 期間は範囲選択可 |
| 日時 | datetime-picker | string(ISO) | 表示はローカル時刻 |
| コード選択 | select（マスタ取得） | string | コード存在チェック |
| マスタ選択 | 選択ダイアログ | string/ID | 検索・複数選択・返却項目を定義 |
| チェック | checkbox/switch | boolean | — |
| ラジオ | radio group | string | 2〜5 択 |
| 添付 | upload | attachment[] | 第 9 章 |
| 明細 | editable table | array | 行操作は [02 画面共通规格](02-common-screen-spec.md) |

### 14.2 入力チェック種別（共通）

| 種別 | 内容 | 既定タイミング |
|---|---|---|
| 必須 | NULL/空文字/未選択を拒否 | フォーカスアウト + 保存時 |
| 型・桁 | 数値/日付/文字数/精度 | 入力時 |
| 範囲 | 数値範囲、日付範囲、文字種 | 入力時 |
| コード存在 | 選択値が有効なマスタに存在 | フォーカスアウト |
| 一意 | 業務キーの重複（例：伝票番号、マスタコード） | 保存時（DB 制約 + 事前チェック） |
| 相関 | 開始日 ≤ 終了日、数量 > 0、単価 ≥ 0 等 | 保存時 |
| 業務チェック | 在庫不足、与信超過、期間締切、承認済み変更不可 等 | 保存/実行時（機能側で定義） |
| 権限 | 操作権限・データ範囲 | 画面表示時 + API 実行時（二重チェック） |

エラー表示は項目単位（項目直下に赤字）＋ 画面上部にエラー一覧。API は `code` / `message` / `fieldErrors[]` を返す（[03 API 共通规格](03-common-api-spec.md)）。

### 14.3 表示・操作の共通規則

- 読み取り専用項目はグレー背景。権限なし項目は**非表示**（値も返さない）。
- コード項目は「コード - 名称」表示（例 `C000123 - 常州泵业有限公司`）。
- ステータスは色付きバッジ：草稿=灰、承認待ち=橙、承認済/発行済=青、一部実行=紫、完了=緑、取消=灰（取消線）、却下=赤。
- 金額は右寄せ、数量は右寄せ、コードは左寄せ。
- 一覧の既定ソート：登録日時の降順（特記ない場合）。ページサイズ既定 20、最大 200。
- 「保存」成功時はトースト通知（3 秒）＋一覧へ戻る（または詳細へ）。「削除」「取消」は確認ダイアログ必須。
- 未保存で画面離脱する場合は警告ダイアログを出す。二重送信はボタン無効化 + 冪等キーで防止。

## 15. データ・マスキング

| データ | 表示 | 保存 | 備考 |
|---|---|---|---|
| パスワード | 表示しない | BCrypt ハッシュ（cost 10 以上） | 平文保存禁止 |
| 银行账号 | 下 4 桁のみ（`**** **** 1234`） | 暗号化（AES-256、鍵は環境変数）を推奨 | 修正は権限者のみ |
| 手机号 | 中间 4 桁マスク（`138****5678`） | 平文可（個人情報保護方針に従う） | エクスポート時もマスク |
| 身份证号 | 生年月日以外マスク | 暗号化推奨 | 原則収集しない |
| 邮箱 | 部分マスク（`a***@example.com`） | 平文 | — |
| 金额・原価 | 権限により非表示可（項目権限） | 平文 | 原価は営業に非公開など |
