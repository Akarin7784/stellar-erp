## 1. 採番・記述規則

| 項目 | 規則 |
|---|---|
| ID | `MSG-PRD-{3桁}`。域内連番。共通で表現できるものは `MSG-COM-xxx` を使用し重複定義しない |
| 種別 | `E`（エラー・処理中断）／`W`（警告・続行可）／`I`（情報・成功）／`C`（確認） |
| 本文 | 中国語。**何が起きたか＋どうすればよいか**を利用者視点で記述。技術用語・スタックトレースを含めない |
| 中文文案 | 画面表示の標準文言（簡体字中国語）。「本文」（日本語）は参考として残す。プレースホルダは本文と同一（蓝色大肥鱼 2026-10-21 决定） |
| プレースホルダ | `{0}`・`{1}` の順序で埋める |
| 業務拒否コード | ドメイン `60000+`（例 `60056`）。**共通 4002 は 422/状態競合専用**で業務拒否に使わない。テナント／`sys_param`（`prd.completion_over_rate` 等）欠落は **5000**。 |
| API エラーコード | 原則 `code = 60000 + メッセージ連番`（例：`MSG-PRD-030` → `code=60030`）。[API 共通规格](../00-common/03-common-api-spec.md) 6.1 の PRD 領域（60000〜69999）に収める |
| 画面表示 | E＝ダイアログ＋項目エラー、W＝トースト（橙）、I＝トースト（緑）、C＝確認ダイアログ（[02 画面共通规格](../00-common/02-common-screen-spec.md) 13 章） |
| ログ | E は WARN/ERROR、W は WARN、I は INFO で出力。個人情報・金額明細を含めない |

## 3. 共通メッセージの利用

本域で共通メッセージを使用する代表例（重複定義しない）：

| 共通 ID | 用途（本域での発生場面） |
|---|---|
| `MSG-COM-033` | 楽観排他競合（BOM・工单・検査・NCR の同時更新） |
| `MSG-COM-034` | 状態不整合（工单・領料・報工・検査の不正状態操作） |
| `MSG-COM-040` | 必須漏れ（品目・数量・検査項目・保留理由） |
| `MSG-COM-044` / `045` / `046` / `047` / `048` | 値域・相関・日付範囲・数量 0 以下・金額負値 |
| `MSG-COM-049` | コード不存在（品目・工作中心・仕入先・検査標準） |
| `MSG-COM-050` | 一意制約（BOM 版本・検査標準・日历） |
| `MSG-COM-070` | 在庫不足（引当・領料・発料） |
| `MSG-COM-071` | 会計期間締切（領料・報工・入庫・検査判定） |
| `MSG-COM-030` / `031` | 権限なし・データ範囲外 |
| `MSG-COM-073` | 承認フロー未設定（工单・BOM 変更・特采） |
