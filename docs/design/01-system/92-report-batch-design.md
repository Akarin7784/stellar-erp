## 4. バッチ詳細

### 4.1 BAT-SYS-001 Outbox 事件配信

| 項目 | 内容 |
|---|---|
| 目的 | 業務トランザクションで記録されたドメインイベントを購読側へ配信する |
| 実行方式 | 固定間隔（10 秒） |
| 想定処理時間 | 1 回 1 秒以内（100 件） |
| 対象データ | `sys_outbox_event WHERE status IN (0,2) AND (next_retry_at IS NULL OR next_retry_at <= now())` |
| 冪等性 | 条件付き（`event_id` 一意 + 購読側重複排除） |
| 排他 | `SELECT ... FOR UPDATE SKIP LOCKED`（多重起動可） |
| 失敗時 | 指数バックオフで再送、10 回失敗で `status=9` + アラート |

**処理手順**：
1. 配信対象を 100 件取得し `FOR UPDATE SKIP LOCKED` でロックする。
2. イベントエンベロープを構築し、Spring Modulith イベントバス（RabbitMQ 外部化も第一版対象）へ配信する。
3. 成功時 `status=1`・`published_at=now()`、失敗時 `retry_count+1`・`next_retry_at` 設定（1 分/5 分/30 分/2 時間/6 時間）。
4. 10 回失敗で `status=9`（DEAD_LETTER）とし、運用担当へ通知する。
5. 配信済みで 3 か月超の行をアーカイブ/削除する。

**更新対象**：`sys_outbox_event.status`、`retry_count`、`next_retry_at`、`last_error`、`published_at`。

### 4.2 BAT-SYS-003 パスワード有効期限提醒

1. `sys_user WHERE status=1 AND password_expire_at BETWEEN now() AND now()+7d` を抽出し、站内 + メールで通知する（同日重複通知は `sys_notification` のシーンキーで抑止）。
2. `password_expire_at < now()` かつ `account_status=1` のユーザを `account_status=4`（密码过期）に更新する。
3. 退職・停用ユーザは対象外。実行結果（通知件数・期限切れ件数）をログに記録する。

### 4.3 BAT-SYS-004 アカウントロック自動解除 / BAT-SYS-005 通知送信リトライ

- BAT-SYS-004：`sys_user WHERE account_status=2 AND lock_until <= now()` を `account_status=1`・`lock_until=NULL`・`login_fail_count=0` に更新する（1 分間隔）。
- BAT-SYS-005：`sys_notification_send_log WHERE send_status IN (0,3) AND next_retry_at <= now()` を 100 件取得し、`FOR UPDATE SKIP LOCKED` で送信する。成功 `2`、失敗 `3` + 再送日時、5 回失敗で `4` 最終失敗 + 運用通知。

### 4.4 BAT-SYS-006 監査日志アーカイブ / BAT-SYS-007 清理

- BAT-SYS-006：3 年超の `sys_audit_log`・`sys_login_log` を月次で `sys_audit_log_archive` へ移管する（TODO：アーカイブ表の DDL が未作成。作成までは対象件数の記録のみで削除しない）。
- BAT-SYS-007：`sys_import_export_job WHERE expire_at < now()` の結果ファイル（`sys_attachment` の一時ファイル）と `sys_idempotency WHERE expires_at < now()` を削除する。1 回 10,000 件ずつ。

### 4.5 BAT-SYS-009 定时任务監視・補償

1. `sys_scheduled_job WHERE status=1 AND next_run_at < now() - 5 分` を抽出し、未実行ジョブを検出する（スケジューラ遅延・停止の検知）。
2. 未実行が 3 回連続した場合はアラート通知する。補償実行は `trigger_type=3` で手動実行を促す（自動再実行はしない: 業務影響を考慮）。
3. 実行中（`end_at IS NULL`）が `timeout_seconds` を超えたジョブを失敗扱いに更新する。

### 4.6 BAT-SYS-010 システム整合性検査 / BAT-SYS-011 キャッシュ再構築 / BAT-SYS-012 初期データ投入

- BAT-SYS-010：01-system/07 章の検査項目を実行し、結果を `sys_data_maintenance_log` に記録する。検出時は運用担当へ站内通知（是正は手動）。
- BAT-SYS-011：辞書・パラメータ・メニュー・権限・組織・採番ルールの Redis キャッシュを再構築する。実行中フラグで二重起動防止。
- BAT-SYS-012：会社（1 件）、工廠（2 件）、部門（8 件）、ロール（18 件）、初期管理者（1 名）、辞書（初期コード）、採番ルール（40 件）、通知テンプレート（10 件）を投入する。存在する場合はスキップ（冪等）。初期管理者の初期パスワードは初回起動時にログ（WARN）へ一度だけ出力し、初回ログインで変更を強制する。詳細データは [94-sample-data.md](94-sample-data.md)。

## 5. 異常処理（バッチ共通）

| 異常 | 検知 | 処理 | 通知 | 再実行 |
|---|---|---|---|---|
| 対象データ不整合 | 件数チェック | 処理中断・ロールバック | 站内 + メール（運用） | 修正後再実行 |
| DB 接続断 | 例外 | リトライ 3 回（指数バックオフ） | 3 回失敗で運用通知 | 可 |
| 多重起動 | 実行中ログ | スキップ（正常扱い） | なし | 不要 |
| タイムアウト | 監視 | 中断・失敗記録 | 運用通知 | 可 |
| 部分失敗 | 件数比較 | 成功分はコミット（設計による） | 結果通知 | 失敗分のみ再実行 |
