## 1. 適用範囲

MDM 域の帳票 15 件、バッチ 10 件、外部 IF 7 件を定義する。帳票は PDF（サーバ生成）を既定とし、[02 画面共通規格](../00-common/02-common-screen-spec.md) 第 14 章に従う。バッチはスケジューラ + `sys_job_result` で実行履歴管理し、冪等性・再実行手順を明記する。

#### B. PRT-MDM-005 客户信用额度一覧表

- 出力項目：客户コード・名称・与信状態・通貨・与信限度額・単一受注上限・超限許容率・超限動作・有効期間・最終審査日。
- 権限：`mdm:credit:view`。財務・経営層のみ全件、営業担当は自部門顧客のみ（データ権限）。
- 並び順：与信状態（凍結→超限→正常）、与信限度額降順。
- 出力条件：基準日時点で有効な与信レコード。

#### C. PRT-MDM-008 供应商评估结果表

- 出力項目：評価期間・供應商コード/名称・品質/納期/価格/服務/技術点・総合点・分级・前月比・コメント。
- 集計：期間平均・分级別件数（A/B/C/D）をフッタに表示。
- 権限：`mdm:supplier-eval:view`（購買・品質・財務）。
- 出力条件：`eval_status=30`（確定済）のみ。未確定は出力不可。

#### D. PRT-MDM-003 物料标签（条码）

- レイアウト：60mm×40mm（ラベルプリンタ）または A4 24 面シート。
- 印字：条码（Code 128）、物料コード、名称（2 行折返し）、規格、単位、批次/序列号、数量、製造日/有効期限（該当時）、会社名。
- 出力条件：有効な条码（`is_active=TRUE`）。最大 500 枚/回。再発行可。
- チェックディジット：Code 128 Mod103（[07](07-substitute-barcode-governance.md) 2.3）。

### 3.1 バッチ詳細（代表 4 件）

#### BAT-MDM-001 汇率导入与生效

| 項目 | 内容 |
|---|---|
| 実行方式 | 日次（取込ファイル配置時のみ実処理。ファイルなしはスキップ） |
| 実行時刻 | 毎日 07:00（取込）、00:10（有効化判定は BAT-MDM-002 と共通化可） |
| 排他 | ジョブ多重起動防止（`sys_job_lock`）。為替テーブルの `(pair,type,date)` upsert |
| 失敗時 | 3 回リトライ（1 分間隔）→ 失敗通知（財務・システム管理者）、前回成功データを維持 |
| 入力 | `90-data` 形式の CSV（`from_currency,to_currency,rate_type,effective_date,exchange_rate,source`） |
| 出力 | `mdm_exchange_rate` upsert、`sys_job_result` 実行履歴 |
| 再実行 | 可能。同日データは上書き（監査ログに差分記録） |

**処理手順**：① 取込ファイル存在チェック → ② ヘッダ・文字コード・必須列検証 → ③ 通貨存在・レート > 0 検証 → ④ upsert → ⑤ 実行履歴・監査ログ → ⑥ 失敗時は全件ロールバック + エラー通知。

#### BAT-MDM-002 价格生效/失效处理

**処理手順**：① 基準日（当日）取得 → ② `status IN (25,30)` の価格表・購買価格を対象に `valid_from <= 今日` かつ `status=25` を有効化（`status=30`）、`valid_to < 今日` を終了（`status=90`）→ ③ 状態変化のあった対象について E04 `mdm.price.changed` を Outbox に INSERT → ④ 実行履歴。**再実行**：状態からの再判定のため冪等。

**異常時**：対象が 0 件でも正常終了。E04 発行失敗は Outbox リトライに委ねる（[09 §10.1](../00-common/09-cross-domain-flow.md)）。

#### BAT-MDM-004 供应商评估月次计算

**処理手順**：① 前月 `YYYY-MM` 決定 → ② 対象供應商抽出（`admission_status IN (30,50)`）→ ③ 品質・納期を PUR/INV の集計 API から取得（未提供時は手動補完フラグ）→ ④ 価格点・服務点・技術点は前月値コピー or 購買担当入力 → ⑤ 総合点・分级算出 → ⑥ `mdm_supplier_evaluation`（`eval_status=10`）INSERT → ⑦ 購買担当へ確定依頼通知（期限：翌月 5 日）。

**冪等**：同一期間の `eval_status IN (10,20)` を削除して再計算。`eval_status=30`（確定済）は変更しない。

#### BAT-MDM-005 主数据质量日检

**処理手順**：① 有効な品質規則を取得 → ② 対象オブジェクトごとに SQL 実行 → ③ 未解決問題（`status IN (10,20)`）と重複する場合はスキップ → ④ 新規問題 INSERT → ⑤ E 重大度は担当・データ治理担当へ通知 → ⑥ 実行履歴・月報基礎データ更新。

**異常時**：1 規則の SQL エラーは該当規則のみスキップして継続（他規則は実行）。エラーは実行履歴に記録し、管理者へ通知。

#### BAT-MDM-007 资质・证照到期预警

**処理手順**：① `mdm_supplier_qualification.valid_to` が本日 +30/15/7/0 日のレコードを抽出 → ② 通知ログ（`sys_notification_log`）で同日重複をチェック → ③ 購買担当・供應商担当・財務へ站内 + メール通知 → ④ 実行履歴。

### 4.1 IF 詳細（IF-MDM-001 汇率导入）

| 項目 | 内容 |
|---|---|
| 方向・頻度 | 受信・日次（07:00） |
| データ量 | 1 回 20〜40 通貨ペア（約 30 行） |

## 5. 帳票・バッチ共通仕様

| 項目 | 内容 |
|---|---|
| 帳票出力権限 | 帳票ごとの `mdm:*:print`。出力履歴を記録し、再出力可 |
| 帳票の非同期化 | 明細 1,000 行超または 500 枚超のラベルは非同期ジョブ（[03 §12](../00-common/03-common-api-spec.md)） |
| バッチ実行履歴 | `sys_job_result`（job_id、batch_id、開始/終了、対象件数、成功/失敗、エラー概要） |
| バッチ失敗通知 | 3 回失敗でシステム管理者 + 運用担当へメール。デッドレターは運用画面で再実行 |
| 月結との関係 | MDM のバッチは会計期間に依存しない（BAT-MDM-004/006 は月次だが会計締めとは独立） |
| 監査 | 帳票出力・バッチ実行・IF 取込を `sys_audit_log` に記録 |
