## 1. 採番・記述規則

| 項目 | 規則 |
|---|---|
| ID | `MSG-INV-{3 桁}`。域内連番。欠番の再利用禁止 |
| 種別 | `E`（エラー・処理中断）/`W`（警告・続行可）/`I`（情報・成功）/`C`（確認） |
| 本文 | **中国語**。利用者視点で「何が起きたか + どうすればよいか」を書く。技術用語・例外名・スタックトレース・SQL を含めない |
| プレースホルダ | `{0}`、`{1}`… の順序で埋める。数量は単位コード付き（例 `{0} {1}` = 数量 + 単位）、金額は元、日付は `yyyy-MM-dd` |
| API エラーコード | `code = 50000 + MSG-INV-NNN`（例 `MSG-INV-001` → `code=50001`）。`00-common/03` §6 の INV 領域 `50000〜59999` に従う |
| 画面表示 | E = ダイアログ + 項目エラー、W = トースト（橙）/ダイアログ、I = トースト（緑）、C = 確認ダイアログ（[02 §13](../00-common/02-common-screen-spec.md)） |
| 共通メッセージ優先 | 共通で表現できる場合は `MSG-COM-xxx` を使用し、本表に重複定義しない（第 4 章） |
| 多言語 | 当面は中国語のみ。第一版 で `messages_inv_zh_CN.properties` / `_en` を追加 |

## 5. メッセージ運用・レビュー観点

| 観点 | 内容 |
|---|---|
| 網羅性 | 各機能文書の「エラー処理」表に記載されたメッセージ ID が本表に存在すること（`20-matrix` で突合） |
| 一意性 | 同一文面を複数 ID で定義しない。共通で表現できるものは `MSG-COM` を優先 |
| 対処可能性 | すべての E/W に「利用者への対処」があること。技術用語を含まないこと |
| プレースホルダ | 本文中の `{n}` と API 応答のパラメータが一致すること（メッセージフォーマット実装時に検証） |
| 状態表示 | E はダイアログ、W はトースト/ダイアログ、I はトースト。確認（C）は OK/キャンセルを明示 |
| 文言の統一 | 「库存」「预留」「盘点」「冲销」「过账」「批次」「序列号」など [07 用語集](../00-common/07-glossary.md) の表記に従う |
| 多言語 | 第一版 で `messages_inv_*.properties` に移行。本文の直書きは禁止（実装時） |
| ログ | E は `WARN`（業務エラー）または `ERROR`（システムエラー）で記録。個人情報・原価を含めない |
