## 1. 攻击场景与指摘

| ID | 重大度 | 攻击场景 | 现状缺口 | 补充设计 |
|---|---|---|---|---|
| G2-01 | **S1** | 两个 MTO 订单抢同一批库存：订单 A 已预留，订单 B 的 MRP 仍把这批算作可用 | 预留不区分专用和通用；MRP 可用量公式没有扣除订单专用库存 | 可用量 = 在库 − 通用预留 − 订单专用库存；订单专用库存只能被所属订单行消耗（§2.1） |
| G2-02 | **S1** | 月结期间仍有人过账，导致成本和总账回写不一致 | 有月结，但「库存期间锁」和「总账期间锁」的先后顺序、锁定后补单的路径没写清 | 顺序：库存关账 → 成本计算 → 总账关账。关账后的业务只能记入下一期，或经审批反开账期。参考 ERPNext Period Closing Voucher 与会计期间关闭 |
| G2-03 | S2 | 工单超领 / 欠领 | 只有 4 处提到「超领」，没有容差参数和审批 | 物料增加超领容差率，超出即走审批；完工时欠领自动生成退料或补领提示。参考 ERPNext Manufacturing Settings 的超额生产 / 超额发料百分比 |
| G2-04 | S2 | 分批收货 / 分批发货后再部分退货 | 退货能否关联到具体某次收货 / 发货行、按原单价冲回，不明确 | 退货行必须带原收货 / 发货行 ID，退货数量 ≤ 已收（已发）− 已退；成本按原入（出）库成本冲回 |
| G2-05 | S2 | 返工：成品检验不合格，返工后再次入库 | 返工成本口径未定（PRD §13 #7） | 建议按独立返工工单处理，关联原工单和 NCR；返工成本记入质量成本，不改原工单的单位成本（**待确认**） |
| G2-06 | S2 | 并发报工：同一工序被两人同时报工，超过上道工序的完工数 | 有乐观锁（`version`），但没有「本工序累计报工 ≤ 上道完工数 + 容差」约束 | 报工过账时对工单工序行加 `SELECT … FOR UPDATE` 再校验 |
| G2-07 | S2 | ECN 生效时已有在制和库存 | 没有处置规则 | ECN 单据增加处置字段（10 用完旧料 / 20 返工 / 30 报废 / 40 立即替换），以及生效方式（日期 / 工单 / 序列号） |
| G2-08 | S2 | 订单变更：客户改了数量或交期，工单已下达 | 销售订单变更后对下游的影响没有定义 | 订单变更走 amend 版本链；数量减少时，提示可取消的工单 / PO，多出的专用库存转为通用库存（需审批） |
| G2-09 | S2 | 作废已有下游的单据 | 单据作废规则分散在各域 | 统一规则：有未作废的下游单据时禁止作废；作废生成红冲分录，不物理删除 |
| G2-10 | S2 | 委外：发料后外协厂退回不良品，或者损耗超标 | 委外损耗率、退回不良品的处理不完整 | 委外单记录允许损耗率；超出部分向外协厂扣款（应付冲减）。参考 ERPNext Subcontracting 的物料平衡 |
| G2-11 | S3 | 盘点期间仍有出入库 | 需确认是否有盘点冻结 | 盘点单范围内的库位冻结；或者用快照 + 期间交易轧差 |
| G2-12 | S3 | 序列号重复 / 跨公司串号 | 序列号唯一索引范围未写清 | 唯一索引 `(company_id, material_id, serial_no) WHERE del_flag = 0` |
| G2-13 | S3 | 报价有效期过期后才转成订单 | 有效期过期时的处理不明确 | 过期报价禁止转单，或者需要重新审批 |
| G2-14 | S3 | 多段报工 / 暂停 | 只有 14 处提到「工时」，没有暂停 / 恢复 | 工时记录拆成多段（开始、结束、暂停原因）。参考 ERPNext Job Card 的 Time Logs |
| G2-15 | S4 | AI 识别字段（如有）缺置信度和人工确认记录 | — | 预留 `ai_confidence`、`confirmed_by`、`confirmed_at` |

## 2. 补充设计（拟新增表，遵守 db-spec）

### 2.1 订单专用库存（MTO 部分）

```sql
CREATE TABLE inv_so_stock (
  id            bigint       PRIMARY KEY,
  company_id    bigint       NOT NULL,
  so_line_id    bigint       NOT NULL,
  material_id   bigint       NOT NULL,
  warehouse_id  bigint       NOT NULL,
  batch_no      varchar(64)  NULL,
  qty           numeric(18,6) NOT NULL DEFAULT 0,
  created_by bigint NOT NULL, created_at timestamptz NOT NULL DEFAULT now(),
  updated_by bigint NOT NULL, updated_at timestamptz NOT NULL DEFAULT now(),
  version int NOT NULL DEFAULT 0, del_flag smallint NOT NULL DEFAULT 0
);
COMMENT ON TABLE  inv_so_stock IS '订单专用库存（MTO）';
COMMENT ON COLUMN inv_so_stock.id IS '主键（雪花 ID）';
COMMENT ON COLUMN inv_so_stock.company_id IS '公司 ID';
COMMENT ON COLUMN inv_so_stock.so_line_id IS '销售订单行 ID';
COMMENT ON COLUMN inv_so_stock.material_id IS '物料 ID';
COMMENT ON COLUMN inv_so_stock.warehouse_id IS '仓库 ID';
COMMENT ON COLUMN inv_so_stock.batch_no IS '批次号';
COMMENT ON COLUMN inv_so_stock.qty IS '专用数量';
COMMENT ON COLUMN inv_so_stock.created_by IS '创建人';
COMMENT ON COLUMN inv_so_stock.created_at IS '创建时间';
COMMENT ON COLUMN inv_so_stock.updated_by IS '更新人';
COMMENT ON COLUMN inv_so_stock.updated_at IS '更新时间';
COMMENT ON COLUMN inv_so_stock.version IS '乐观锁版本';
COMMENT ON COLUMN inv_so_stock.del_flag IS '删除标志 0 正常 1 删除';
CREATE UNIQUE INDEX uk_inv_so_stock ON inv_so_stock(company_id, so_line_id, material_id, warehouse_id, COALESCE(batch_no,'')) WHERE del_flag = 0;
```

审计列名称按 db-spec 实际定义对齐（实现时以 db-spec 为准）。

### 2.2 ECN 单据（`prd_ecn` 表头 / `prd_ecn_line` 明细）

- 表头：`ecn_no`（业务键，部分唯一）、`company_id`、`source_type`（10 设计改进 / 20 客户订单驱动 / 30 质量问题）、`so_line_id`（订单驱动时必填）、`effect_mode`（10 日期 / 20 工单 / 30 序列号）、`effect_date`、`status`（10 草稿 → 20 审批中 → 30 已批准 → 40 已生效 / 90 已作废），以及审计列。
- 明细：`bom_id`、`old_bom_version`、`new_bom_version`、`material_id`、`change_type`（新增 / 删除 / 替换 / 改用量）、`disposition`（10 用完 / 20 返工 / 30 报废 / 40 立即替换）。
- 每列都要有 COMMENT；`ecn_no` 唯一索引带 `WHERE del_flag = 0`。

### 2.3 订单 BOM / 报价估算 / 订单成本

- `prd_bom.bom_scope`：10 标准，20 订单专用。订单专用时 `so_line_id` 必填，MRP 对该订单行优先使用订单 BOM。
- `sal_quotation_cost_line`：报价成本估算行，类型分为材料 / 工时 / 委外 / 制造费用，单价**不含税**；制造费用单独成行，不并入直接成本对比。
- `fin_cost_collection.cost_object_type`：增加 30（销售订单行）。月结时把关联的工单、委外单和直接采购汇总到订单行，与报价估算逐行比较。
