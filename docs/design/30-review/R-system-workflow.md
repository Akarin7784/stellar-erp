## 4. 未検証範囲・制約

1. **外部実仕様の最終確認は不能**：銀行 Adapter（MT940/回单形式）、税局/服务商 API の実エンドポイント・証明書・項目コードは契約・仕様書が未提供のため検証できない。設計は「創作しない」方針を明記しており妥当（`:41`）。
2. **Web 事実確認の制約**：`www.gov.cn` への直接アクセスは実行環境のネットワーク制限（non-public IP）で失敗した。数电票公告・小規模納税人 1% 政策は検索結果の税務局掲載ページ・見出しで確認したが、条文全文の逐条確認はできていない（税務専門担当の再確認を推奨）。
3. **90-data の出典真正性**：本レビューでは 06-code-list/90-data との**数値・コードの整合**のみ確認した。出典 URL の実在性・参照日は data-researcher のレビュー範囲であり、重複レビューはしていない。
4. **09-integration の全画面項目定義（24 画面）**：本文通読は主要 5 ファイルに限定。画面項目の型/桁の網羅チェックは未実施（ファイル数 11 のうち 6 ファイルは章単位閲覧）。
5. **S1 判定なしの理由**：実データ捏造・法令違反の**確証**は得られなかった（保存期間は「要確認」表記があり、S2 として指摘）。S1 は「そのまま実装すると業務・会計・法令が破綻」と確証できる場合のみ付す方針とし、本ラウンドでは該当なし。

## 5. 総評（実装可否判断）

**条件付可（S2 6 件の修正後に実装着手可）**

- 00-common は全体として粒度が高く、精度・税計算・移動平均・イベントエンベロープ・Outbox 補償・セキュリティの基本設計は実装可能な水準にある。特に 09-integration が「実在しないエンドポイント/証明書を創作しない」と明記し、示例ドメインのみを使用している点は高く評価できる。
- ただし **S2 6 件**（P2P の E05 誤用、INT 状態コードの意味衝突、`code=5001` の二重定義、与信承認経路の矛盾、発票保存期間の矛盾、Outbox DDL の二重定義）は、いずれも**実装すると購読/承認/エラー分岐/データ保持のいずれかが破綻する**ため、実装前に修正が必要。
- S3 10 件は主に語彙・陳腐化・層別ルールの不足であり、実装開始前の一括修正で解消可能。
- 推奨修正順：①REV-SW-001/004（業務フロー・統制）→②REV-SW-002/003（コード体系）→③REV-SW-005/006（法令・基盤テーブル）→④S3 一括（REV-SW-007〜016）→⑤S4。
