## 1. 目的

詳細設計書は「完成・校验 0 指摘」の状態にあるが、それは**自己整合性**の確認にすぎない。実装着手前に、設計を**意図的に破壊しにいく**第三者レビュー（红队）を行い、次を摘出する。

1. **致命矛盾**：ある文書の定義が別文書と両立せず、そのまま実装すると業務が破綻するもの。
2. **実装不能・未定義**：算法・項目・状態・エラー処理が不足し、開発が判断できないもの。
3. **データの虚偽・誤り**：実在しない標準・誤った税率/科目・検証不能な出典・数値の不整合。
4. **法令・会計・税務の違反リスク**。
5. **業務漏れ**：国内製造業 ERP として当然必要な機能・帳票・統制の欠落。
6. **テスト不能**：テスト観点が検証可能な形になっていない。

## 2. 独立性原則

- レビュアーは**自分の担当域をレビューしてはならない**（作者バイアス排除）。
- レビュアーは設計・数値の「正しさ」を前提にしない。**反例を探す**。
- 指摘は必ず**証拠（ファイル:行・引用・参照先）**を付ける。推測は「推測」と明記する。
- **指摘を捏造しない**。問題がなければ「問題なし」と証拠付きで書く。件数を稼ぐための指摘は禁止。

## 3. 攻撃次元（A〜H）

| # | 次元 | 攻撃内容（例） |
|---|---|---|
| A | 業務完备性 | 国内製造業 ERP の標準機能・帳票・統制の欠落。異常系・取消・訂正・返品・部分処理の抜け |
| B | 跨域契約矛盾 | イベント payload・状態コード・採番・テーブル/項目名・責任分界が文書間で食い違う。循環依存・二重更新 |
| C | データ真正性 | 標準号・税率・CAS 科目・CNAPS・HS・行政区画・企業情報の誤り/創作。出典の実在性・参照日。数値例の計算誤り |
| D | 実装可能性 | 算法（MRP・移動平均・税・按分）の手順不足、同時実行、排他、性能、DB 制約、冪等性、障害復旧 |
| E | 法令・会計・税務・情報 | 会計档案保存、発票、税額計算、個人情報、監査ログ、SoD、電子データ |
| F | 文書品質（日式詳細設計） | 項目定義の欠落（型/桁/必須/校验/DB 項目）、処理詳細の曖昧表現、テスト観点の検証不能、未決の放置 |
| G | 権限・セキュリティ | 画面/API/項目/データ範囲の不整合、越権、マスキング漏れ、監査証跡 |
| H | 数値・整合 | 貸借一致、BOM/原価/在庫金額/税額/KPI の再計算一致、例示値のトレーサビリティ |

## 4. 指摘の重大度

| 重大度 | 定義 | 対応 |
|---|---|---|
| **S1 致命** | そのまま実装すると業務・会計・法令が破綻。または根拠のない実データ記載 | 実装前に**必須修正** |
| **S2 重大** | 主要機能の仕様不足・跨域矛盾・計算誤り。実装時に手戻り大 | 実装前に**修正必須**（設計変更伴う） |
| **S3 一般** | 局所的な不整合・記述不足・用語/ID の揺れ | 実装開始までに修正 |
| **S4 建議** | 改善提案・将来検討 | 任意（未決/課題として記録） |

## 5. 出力フォーマット（各レビュアー）

`docs/design/30-review/R-{reviewer}.md` に以下を書く（他のファイルは編集しない）。

1. 文書情報（DSN-REV-xxx、レビュアー、対象域、版数）
2. レビュー範囲・方法・実施日
3. **指摘一覧**（下表）
4. 検証して問題なかった項目（対象×観点のカバレッジ証跡）
5. 未検証範囲・制約
6. 総評（実装可否判断：可 / 条件付可 / 不可）

| 指摘 ID | 重大度 | 対象ファイル:行 | 指摘内容 | 証拠・根拠 | 修正提案 | 想定影響 |
|---|---|---|---|---|---|---|
| REV-{name}-001 | S1/S2/S3/S4 | `xx/yy.md:123` | … | 引用/計算/参照 | … | … |

## 7. 禁止事項

- 設計ファイルの修正（指摘のみ。修正は別ラウンドで所有者が行う）。
- git commit。
- 根拠のない「実データ」判定、出典の捏造、指摘件数の水増し。
- 対象外ファイルへの書き込み（自分の `R-*.md` のみ）。
