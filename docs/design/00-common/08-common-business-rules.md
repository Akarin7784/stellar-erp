## 1. 適用範囲

複数の業務域にまたがる共通ルール（採番・状態・計算・税・単位・原価・承認・権限・期間・保存）を定義する。各域の設計書は本ルールを前提とし、逸脱する場合は理由を明記する。**本ルールの変更は全ドメインに影響するため Lead 承認を必須とする。**

- 日付は**採番実行日**（業務日付ではない）。取消・再作成でも新しい番号を採番する（欠番許容）。
- プレフィックスと日付の間、日付と連番の間に区切り文字は入れない（外部連携先の桁数制約に配慮）。可読性のため画面表示では `SO-261020-0001` のようにハイフン表示してよいが、保存値は区切りなし。
- 状態変換（ST_IN/ST_OUT）は独立した伝票番号を持たない。来源单据（IQC/盘点/手工）を source とし、`pair_key` で対になる 2 取引を関連付ける。ただし在庫域内の管理用に内部番号 `ST{YYMMDD}{4}` を付してよい（**業務伝票番号ではなく、帳票・対外文書には使用しない**）。
- **在庫側伝票の採番所有権**：`MII`（生産領料）`MIR`（生産退料）`FGI`（完成品入庫）`OSI`（委外発料）`OSR`（委外受入）の伝票番号は **INV が単一所有・採番**する（`inv_stock_txn.txn_no` と 1:1）。PRD は要求/実績データ（数量・工単・理由）のみを保持し、伝票番号は INV が返す `stock_doc_id/stock_doc_no` を参照する（PRD 側で同一プレフィックスを再採番しない）。
- 盤盈盤亏・調撥・成本調整・状態変換・その他入出庫の承認閾値は 8.1 の表に従う（金额は税込・【示例值】、参数化）。
- 採番失敗（DB エラー）時はトランザクション全体をロールバックし、番号を消費しないことを保証する（採番はトランザクション内で実行）。
- 承認取消・再提出では番号を変えない（同一伝票の状態遷移）。

### 2.3 外部参照番号

顧客注文番号・仕入先注文番号・請求書番号・送り状番号などは `external_no` として保持し、原票どおりの文字列を保存する（前後空白のみトリム）。重複チェックは業務上の必要性に応じて行う。

### 3.3 ステータス遷移の共通制約

1. 許可されない遷移は `MSG-COM-034`「該記録は現在の状態ではこの操作を実行できません」で拒否する。
2. 状態遷移は**楽観排他（version）付き**で実行し、同時承認・同時取消を防ぐ。
3. 承認済（25）以降の内容変更は禁止。変更は「変更伝票」または「取消→再作成」で行う（受注変更・発注変更は専用機能で版数を管理）。
4. 取消（90）は後続処理が存在しない場合のみ可能。在庫・会計の逆処理が必要な場合は先に下流の取消を行う（`MSG-COM-072`）。
5. 完了（40）からの再開は禁止。返品・追加出荷等は新規伝票で処理する。

## 4. 金額・税額の計算

### 4.1 基本方針

| 項目 | 決定 |
|---|---|
| 税方式 | 中国増値税（一般納税者）。税率は税コード（MDM）で管理 |
| 単価 | **税抜単価**を基本とする（税込単価を入力した場合は税抜へ換算して保存し、税込単価も保持可） |
| 税計算単位 | **明細行単位**で計算し、伝票合計は明細の合計（伝票全体での再丸め禁止） |
| 端数 | 四捨五入（0.5 は切り上げ）。Java `BigDecimal.setScale(n, RoundingMode.HALF_UP)` |
| 表現 | 税抜金額・税額・税込金額の 3 つを保持・表示する |
| 税率 | 標準 13%、適用税率は品目・取引内容で決定（[06 代码一览](06-code-list.md)）。税率変更は新税コードで管理し、既存伝票は登録時点の税率を保持 |

### 4.2 計算式

| # | 計算 | 算式 | 丸め |
|---|---|---|---|
| 1 | 行金額（税抜） | 数量 × 税抜単価 | 数量 4 桁 × 単価 6 桁 → 四捨五入 2 桁 |
| 2 | 行税額 | 行金額（税抜）× 税率 | 四捨五入 2 桁 |
| 3 | 行税込金額 | 行金額 + 行税額 | — |
| 4 | 伝票税抜合計 | Σ 行金額 | — |
| 5 | 伝票税額合計 | Σ 行税額 | — |
| 6 | 伝票税込合計 | 税抜合計 + 税額合計 | — |
| 7 | 税込単価 → 税抜単価 | 税込単価 ÷ (1 + 税率) | 四捨五入 6 桁 |
| 8 | 行割引（率） | 行金額 × (1 − 割引率) | 四捨五入 2 桁 |
| 9 | 伝票値引の按分 | 値引額 × 行金額 ÷ 税抜合計 | 各明細で四捨五入 2 桁。差額は最終明細に寄せる |
| 10 | 為替換算 | 外貨金額 × レート | 四捨五入 2 桁。レートは 8 桁保持 |

### 4.3 計算例（YE3-100L1-4、税率 13%）

| 項目 | 例 1（税抜単価） | 例 2（税込単価入力） |
|---|---|---|
| 数量 | 120 PCE | 120 PCE |
| 単価 | CNY 856.500000（税抜） | CNY 967.845000（税込） |
| 税抜単価換算 | — | 967.845000 ÷ 1.13 = 856.500000 |
| 行金額（税抜） | 120 × 856.50 = 102,780.00 | 102,780.00 |
| 税額（13%） | 102,780.00 × 13% = 13,361.40 | 13,361.40 |
| 税込金額 | 116,141.40 | 116,141.40 |

> 上記の単価・数量は **【示例値】**（設計検証用）。実データではない。

### 4.4 端数差の処理

- 値引・按分・為替換算で生じた差額は、**最終明細または指定明細**に加減算し、どの行に寄せたかを `rounding_target_line_no` に記録する。
- 税額の合計が税務申告額と一致しない場合（明細丸めの累積差）、伝票単位の調整行を設けず、明細丸めの合計を正とする（申告時に調整）。
- 金額 0 の明細は保存可（サンプル品・無償提供）。ただし税額計算は行う。

## 5. 単位換算

| 項目 | 規則 |
|---|---|
| 単位グループ | 同一グループ内で換算（例：PCE / SET / DZ、KGM / G）。異種グループ間の換算禁止 |
| 基本単位 | 在庫管理単位（例：PCE、KGM） |
| 購入単位 | 仕入先からの受入単位（例：箱、巻）。`conversion_rate` = 1 購入単位あたりの基本単位数 |
| 販売単位 | 顧客への販売単位（例：台、セット） |
| 換算方向 | 数量 × 換算率 = 基本単位数量。逆算は除算し、丸めは基本単位の精度（数量 4 桁）で行う |
| 換算差 | 購入数量が換算で端数になる場合は、**整数単位に切り上げ/切り捨ての業務ルール**を機能側で定義（例：発注は箱単位、在庫は PCE 単位） |
| 表示 | 購入・販売画面では取引単位で入力・表示し、在庫数量は基本単位で表示（併記可） |
| 変更 | 換算率の変更は有効期間で管理し、既存伝票は登録時点の換算率を保持 |

## 6. 库存计价（移动加权平均法）

### 6.1 基本定义

| 項目 | 定義 |
|---|---|
| 计价方法 | 标准成本第一版启用；库存计价口径待业务确认（A：移动加权平均计价＋标准成本仅差异分析；B：标准成本计价＋差异入差异科目）。标准成本唯一来源待定 |
| 平均单价精度 | 6 桁（元/基本单位）。表示は必要に応じ 2〜6 桁 |
| 入庫原価 | 采购单价（税抜）+ 运费分摊 + 关税 + 其他可直接归属费用。運費按数量或金额分摊 |
| 出庫原価 | 出庫数量 × 出庫時点の平均単価。四捨五入 2 桁 |
| 残高 | 在庫数量・在庫金額・平均単価を `inv_stock_balance`（倉庫 × 物料 × 批次）に保持 |
| マイナス在庫 | **P0 は禁止**（設定 `allow_negative_stock=false`）。引当・出庫時に不足チェック |
| 遡及取引 | 禁止。在庫取引日は「当該物料・倉庫の最終取引日」以降でなければならない（修正は取消→再登録） |
| 原価調整 | 請求書価格と暫估価格の差異、運費差異は `inv_cost_adjustment` で調整し、在庫金額・平均単価を更新 |

### 6.2 計算式

```
入庫後平均単価 = (旧在庫金額 + 入庫金額) ÷ (旧在庫数量 + 入庫数量)   ※ 6 桁丸め
出庫金額（行） = 出庫数量 × 出庫前平均単価                            ※ 2 桁丸め
入庫金額 = Σ(入庫数量 × 入庫単価) + 分摊运费等                        ※ 2 桁丸め
在庫金額 = 旧在庫金額 + 入庫金額 − 出庫金額
```

> 数値は計算例（示例値）。実際は全量を `NUMERIC` で保持し、表示時のみ丸める。

### 6.4 原価調整

- 暫估入庫後に請求書が届き、単価差異が生じた場合：差異額を在庫金額に加減し、平均単価を再計算する。既に出庫済みの数量分は **当期の売上原価または製造原価** に振り替える（差異が僅少な場合は当期費用処理、閾値は `sys_param`）。
- 差異調整の結果、在庫金額が負になる場合は調整を拒否し、手動調査とする。
- 原価調整は**期間関账前**のみ実行可能。

## 7. 库存評価・棚卸差異

| ケース | 処理 |
|---|---|
| 棚卸差異（盤盈） | 実在庫 > 帳簿：`inv_stock_txn`（ADJ_IN）登録、原価は現在の平均単価。会計は「待処理財産損益」経由で処理 |
| 棚卸差異（盤虧） | 実在庫 < 帳簿：`inv_stock_txn`（ADJ_OUT）登録。原因区分（管理不善/自然损耗/災害）に応じ会計処理を分岐 |
| 差異承認 | 棚卸差異は承認後に在庫調整を実行（承認なしの調整禁止） |
| 差異の閾値 | 金額・数量の閾値を超える差異は上位承認（[90-data/approval-matrix.md](../90-data/approval-matrix.md)） |

## 8. 承認マトリクス

### 8.1 承認対象と経路（示例企業）

| 対象 | 条件（金額は税込） | 承認経路 | 方式 |
|---|---|---|---|
| 采购申请 PR | 5,000 元未満 | 部門经理 | 或签 |
| 采购申请 PR | 5,000〜50,000 元 | 部門经理 → 采购经理 | 順送 |
| 采购申请 PR | 50,000〜500,000 元 | 部門经理 → 采购经理 → 分管副总 | 順送 |
| 采购申请 PR | 500,000 元以上 | 上記 + 总经理 | 順送 |
| 采购订单 PO | 依頼金額に準拠 | PR と同じ経路（PR 承認済の場合は短縮可） | 順送 |
| 销售订单 SO | 標準価格の ±5% 以内 | 销售经理 | 或签 |
| 销售订单 SO | 折扣 5〜10% | 销售总监 | 或签 |
| 销售订单 SO | 折扣 10% 超 / 信用超過 | 销售总监 → 财务总监 → 总经理 | 順送 |
| 采购退货 PRT | 全額 | 采购经理 → 财务经理 | 順送 |
| 销售退货 SRT | 全額 | 销售经理 → 财务经理 | 順送 |
| 付款申请 PA | 50,000 元未満 | 财务经理 | 或签 |
| 付款申请 PA | 50,000〜500,000 元 | 财务经理 → 财务总监 | 順送 |
| 付款申请 PA | 500,000 元以上 | 財務总监 → 总经理 | 順送 |
| 费用报销 | 5,000 元未満 | 部門经理 → 财务复核 | 順送 |
| 费用报销 | 5,000 元以上 | 部門经理 → 财务经理 → 总经理 | 順送 |
| 主数据变更（价格・信用・銀行口座） | 全件 | 主管部门長 → 财务/采购/销售責任者 | 順送 |
| 盘盈盘亏 | 金額 10,000 元未満 | 倉庫主管 → 财务经理 | 順送 |
| 盘盈盘亏 | 10,000 元以上 | 上記 + 总经理 | 順送 |
| 在庫調撥（跨倉・有償/無償を問わず） | 移動金額 10,000 元未満 | 倉庫主管 | 或签 |
| 在庫調撥（跨倉） | 移動金額 10,000 元以上 | 倉庫主管 → 财务经理 | 順送 |
| 在庫成本調整 | 差異 1,000 元未満 | 财务经理 | 或签 |
| 在庫成本調整 | 差異 1,000 元以上 | 财务经理 → 财务总监 | 順送 |
| 在庫状態変換（待検→不合格/廃棄） | 全件 | 品質主管 → 倉庫主管 | 順送 |
| その他入出庫（AOI/AOO） | 金額 10,000 元以上 | 倉庫主管 → 财务经理 | 順送 |

> 上記は**示例企業の社内規程（仮定値）**。実運用では顧客企業の規程に合わせて設定する。金額閾値・経路はパラメータ（`wf_approval_matrix`。WF 域が所有）で管理し、ハードコードしない。**詳細シナリオ（A01〜A20 の条件・承認経路・方式）は [90-data/approval-matrix.md](../90-data/approval-matrix.md) を正本**とし、本表の概略と細目が異なる場合は同シナリオ表を優先する（本表は原則・概略を示すもの）。

### 8.2 承認の共通ルール

| 項目 | 規則 |
|---|---|
| 申請者と承認者 | 同一人物は承認不可（自己承認禁止）。承認者が不在の場合は代理承認者を設定 |
| 差戻し | 承認者は理由付きで差戻し可能。差戻し後は申請者が修正して再提出 |
| 却下 | 却下は終端。再申請は新規伝票 |
| 撤回 | 申請者は未処理の承認者のみ撤回可能（既に承認された後の撤回不可） |
| 加算承認（加签） | 承認者は前後任意に承認者を追加可能（追加分の承認完了後に続行） |
| 転送（转办） | 承認者は自分のタスクを他の承認者へ転送可能（ログ必須） |
| 会签・或签 | 会签 = 全員承認で通過、或签 = 1 名承認で通過。フロー定義で指定 |
| エスカレーション | 承認待ち 24 時間でリマインダ、48 時間で上位者へエスカレーション（設定可） |
| 代理承認 | 期間を指定して代理を設定。代理の承認も監査ログに記録 |
| 承認コメント | 承認は任意、却下・差戻しは必須 |
| 承認後の変更 | 不可。変更は変更伝票または取消→再作成 |

## 9. 権限・職務分掌（SoD）

### 9.1 ロール（示例企業）

| ロール | 主な権限 | 制約 |
|---|---|---|
| 系统管理员 | ユーザ・ロール・メニュー・パラメータ・監査ログ参照 | 業務伝票の作成・承認は不可 |
| 总经理 | 全社の参照・高額承認 | 伝票の作成は原則不可 |
| 财务总监 | 会計・資金・与信の承認、財務参照 | 伝票作成は不可（会計承認のみ） |
| 财务经理 | 会計処理、支払承認（閾値内）、月結 | 支払実行は不可 |
| 会计 | 凭证作成、应收应付、对账、报表 | 凭证審査・記帳は不可（他人が実施） |
| 出纳 | 入出金実行、銀行対账 | 凭证作成・承認は不可 |
| 采购经理 | 発注承認、仕入先管理 | 受入・検収は不可 |
| 采购员 | 請購・発注・納期追跡 | 発注承認・受入は不可 |
| 销售经理 | 受注承認、価格承認（閾値内） | 出荷・入金処理は不可 |
| 销售员 | 見積・受注・顧客対応 | 受注承認は不可 |
| 生产经理 | 工単承認、生産計画 | 材料出庫・受入は不可 |
| 计划员 | MRP 実行、工単作成、日程計画 | 工単承認は不可 |
| 车间主管 | 作業指示、報工承認 | 会計処理は不可 |
| 仓管员 | 入出庫、棚卸実行 | 棚卸承認・会計処理は不可 |
| 质检员 | 検査登録、合否判定 | 入荷・出荷数量の変更は不可 |
| 部门经理 | 部門予算・請購承認 | 自己の申請は承認不可 |

### 9.2 職務分掌（SoD）ルール

| # | 分離すべき職務 | 理由 | 強制方法 |
|---|---|---|---|
| 1 | 請購作成 ⇔ 請購承認 | 不正発注防止 | ロール分離 + 自己承認禁止 |
| 2 | 発注 ⇔ 受入・検収 | 架空発注・横領防止 | ロール分離 |
| 3 | 受入 ⇔ 検収 | 品質・数量の相互牽制 | ロール分離 |
| 4 | 支払申請 ⇔ 支払実行 | 不正送金防止 | ロール分離 |
| 5 | 凭证作成 ⇔ 审核 ⇔ 記帳 | 会計不正防止 | ロール分離（財務責任者確認） |
| 6 | マスタ登録 ⇔ マスタ承認 | 架空取引先・口座変更防止 | 承認フロー |
| 7 | 棚卸実施 ⇔ 棚卸承認 ⇔ 在庫調整 | 在庫横領防止 | ロール分離 |
| 8 | 銀行口座変更 ⇔ 承認 | 振込先詐欺防止 | 承認 + 監査ログ + 変更通知 |

- SoD はロール設計で担保し、権限設定時にチェックする（同一ユーザへの相反ロール付与は警告）。
- 職務分掌上やむを得ず兼任する場合は、上位承認と監査ログで補完する（設定で許可、理由必須）。

## 10. 会计期间・关账

| 項目 | 規則 |
|---|---|
| 年度 | 1 月 1 日〜12 月 31 日（中国法定会計年度） |

## 11. 主数据管理ルール

| 項目 | 規則 |
|---|---|
| 新規登録 | 重複チェック（コード・名称・税号・銀行口座）→ 承認 → 有効化。承認前は業務利用不可 |
| 変更 | 重要項目（価格、与信限度、銀行口座、税区分、BOM、工艺）は変更承認フロー必須。変更履歴を `*_his` に記録 |

| データ品質 | 必須項目の充足率、重複率、コード規則違反を月次でモニタリング（`BAT-MDM-xxx`） |
| 一括更新 | マスタの一括更新はインポート機能 + 承認で実施。直接 SQL 更新は禁止 |
| マスタ配布 | 多拠点時は本社マスタを配布し、拠点固有項目のみ拠点管理（Phase 2） |

## 13. 共通処理ルール

### 13.1 取消・訂正

| 種別 | ルール |
|---|---|
| 伝票取消 | 後続処理がない場合のみ。在庫は逆仕訳、会計は赤伝または逆仕訳で戻す。取消理由必須。監査ログ記録 |
| 会計訂正 | 確定済み凭证は直接修正禁止。赤伝（マイナス仕訳）で訂正し、新規凭证を起票 |
| 在庫訂正 | 取消→再登録。遡及修正禁止（6.1） |
| マスタ訂正 | 変更履歴を残して更新。コード変更は禁止（新コード発行） |

### 13.2 一括処理・インポート

- 一括処理は全件成功 or 全件失敗を既定とする。部分成功を許す場合は結果一覧を必ず返す（[02 画面共通规格](02-common-screen-spec.md) 4.3）。
- インポートは「検証（ドライラン）→ 実行」の 2 段階。検証結果（エラー行・理由）をダウンロードできる。
- インポートの最大行数は 10,000 行/回。超過は分割または非同期ジョブ。

### 13.3 通知

| トリガ | 通知先 | 手段 | タイミング |
|---|---|---|---|
| 承認依頼 | 承認者 | 站内 + メール（設定） | 即時 |
| 承認結果 | 申請者 | 站内 | 即時 |
| 承認遅延 | 承認者・上位者 | 站内 + メール | 24h/48h |
| 在庫不足・安全在庫割れ | 計画・購買 | 站内 | 日次 |
| 納期遅延 | 購買・営業 | 站内 | 日次 |
| 与信超過 | 営業・財務 | 站内 | 即時 |
| バッチ失敗 | システム管理者・運用 | メール | 即時 |
| 外部 IF 失敗 | 運用担当 | メール + 站内 | 即時（連続失敗時） |

- 通知は送信失敗しても業務処理をロールバックしない（非同期・再送）。
- 通知設定はユーザ・ロール単位で ON/OFF 可能。

### 13.4 添付・コメント

- 添付・コメントは業務データの補助であり、業務判断の根拠を添付のみに依存させない（必須判断はデータ項目で持つ）。
- コメントは追記のみ（編集・削除不可）。削除が必要な場合は管理者が非表示にする。
