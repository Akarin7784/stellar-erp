## 4. 承認方式（固定区分）

| 値 | 名称 | 意味 | 使用例 |
|---|---|---|---|
| `OR` | 或签 | 承認者のうち 1 名の承認で通過 | 部門经理・销售经理・财务经理の単独承認 |
| `SEQ` | 順送 | 指定順に全員承認で通過 | 部門经理→采购经理→分管副总 |
| `AND` | 会签 | 指定全員の承認で通過 | 高額・特別案件（本示例では未使用） |

## 5. 金額・条件の判定ルール

1. **金額の確定時点**：伝票の明細合計（税込）が確定した時点で承認経路を決定する。明細追加・単価変更により閾値を跨いだ場合は**経路を再評価**する。
2. **通貨**：外貨伝票は取引日レートで CNY 換算して閾値判定する（[06](../00-common/06-code-list.md) §4）。
3. **税込／税抜**：08 章 8.1 の「金額は税込」に従い、税込合計で判定する。ただし与信管理は税抜・税込の定義を [03-sales](../README.md) 側で統一する。
4. **複数条件の優先**：同一伝票に複数条件（例：折扣 10% 超かつ信用超過）が該当する場合は、**最も上位の経路**（A08）を適用する。
5. **承認済の再変更**：承認後の内容変更は不可。変更伝票または取消→再作成（[08](../00-common/08-common-business-rules.md) 8.2）。
6. **代理承認**：期間指定の代理を設定可能。代理承認も監査ログに記録する。
7. **エスカレーション**：承認待ち 24 時間でリマインダ、48 時間で上位者へエスカレーション（設定可）。
8. **タイムアウト自動承認**：本示例では**自動承認しない**（明示承認のみ）。

## 6. システム実装方針（WF 域との契約）

| 項目 | 内容 |
|---|---|
| 管理テーブル | `wf_approval_matrix`（対象コード・条件種別・閾値下限・上限・通貨・承認順・役割コード・方式・有効期間） |
| 流程定義 | Flowable のプロセス定義キー（例 `APR-SO-L3`）。バージョン管理し、実行中インスタンスは開始時バージョンに固定 |
| 業務側インターフェース | 業務域は「対象コード＋金額＋通貨＋条件属性（折扣率・信用超過フラグ等）」を渡して承認要否・経路を照会する（`POST /api/workflow/approval-routes:resolve` 等。API の正本は [03-common-api-spec](../00-common/03-common-api-spec.md)） |
| 状態連携 | 業務伝票は `10 草稿 → 20 承認待ち → 25 承認済`。却下は `95`、取消は `90`（[08](../00-common/08-common-business-rules.md) §3） |
| 承認結果 | 承認完了イベント（例 `workflow.task.completed`）で業務域へ通知し、業務状態を更新（[09](../00-common/09-cross-domain-flow.md) 第 9 章） |
| 監査 | 申請・承認・差戻し・却下・代理・転办・加签を `sys_audit_log` に記録（誰が・いつ・何を・理由） |
| パラメータ変更 | 閾値変更は主データ変更として承認（A16）＋監査ログ。変更履歴を保持し、過去の承認判断には影響させない |
| データ移行 | 初期値は本文件の表をシードとして投入。会社規程の改定時は `valid_from` で新行を追加し、旧行を `valid_to` で閉じる |

| 列 | 意味 | 例 |
|---|---|---|
