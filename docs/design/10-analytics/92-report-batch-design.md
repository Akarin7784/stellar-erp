## 1. 適用範囲

本設計書は RPT 域の帳票（PRT-RPT-xxx）とバッチ（BAT-RPT-xxx）を定義する。帳票は分析結果の**配布・保存**を目的とし、業務伝票（発注書・請求書等）は各業務域が保有する。バッチは抽出・KPI 計算・予警評価・配信・整合性検査を担う。

**帳票の共通仕様**：PDF を既定、Excel は分析用。出力には「期間・作成日時・作成者・口径注記」を必ず印字する。月次未確定の場合は「暫定」を透かし表示する。出力履歴を `sys_print_log` と `rpt_query_log` に記録する。

## 5. バッチ詳細

### 5.1 BAT-RPT-001 销售明细抽出

| 項目 | 内容 |
|---|---|
| 実行方式 | 日次 01:00 |
| 対象 | `sal_delivery_note.confirmed_at::date = 前日` かつ `delivery_status=40` |
| 処理 | 日付分を削除→出荷明細・返品を INSERT→件数・金額検証 |
| 入力 | `sal_delivery_note(_line)`、`sal_sales_order(_line)`、`sal_sales_return(_line)`、`mdm_material`、`mdm_customer` |
| 出力 | `rpt_sales_detail`、`rpt_etl_job` |
| 冪等 | 日付単位で全削除→再作成 |
| 異常 | 金額不一致はロールバックし `MSG-RPT-030`。0 件は正常 |
| 再実行 | 可（同日付） |

| 再実行 | 可 |

### 5.3 BAT-RPT-003 库存快照抽出

| 項目 | 内容 |

| 監視 | 失敗時は `MSG-RPT-030` を通知。連続 2 回失敗で情報部長へ |
| 再実行 | 全バッチ再実行可。二重起動はジョブのロックで防止 |
| 保存 | 実行履歴 2 年、抽出エラー 2 年、整合性検査 3 年 |
