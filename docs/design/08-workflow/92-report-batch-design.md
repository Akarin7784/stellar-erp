## 4. バッチ詳細

### 4.1 BAT-WF-001 超時タスク検出・リマインダ

| 項目 | 内容 |
|---|---|
| 目的 | 期限内に処理されていない承認タスクを検出し、承認者へリマインダを送る |
| 実行方式 | 固定間隔 5 分 |
| 対象 | `wf_task WHERE task_status=20 AND due_at <= now()` |
| 冪等性 | `wf_timeout_record (task_id, record_type=1)` の存在で抑止 |
| 排他 | `SELECT ... FOR UPDATE SKIP LOCKED` |
| 失敗時 | ログ記録、次回実行で再処理（冪等） |

**処理手順**：
1. 対象タスクを最大 1,000 件取得する。
2. 適用タイムアウト規則を解決する（業務類型・ノード・優先度、なければ既定 24h/48h）。
3. 営業時間ベースの経過時間を計算する（`sys_param: workflow.work-calendar`）。
4. `reminder_hours` を経過し未通知の場合、`WF_TASK_TIMEOUT` を通知し、`wf_timeout_record` に `record_type=1` を INSERT、`wf_task.reminder_count+1` に更新する。
5. 結果件数を `sys_scheduled_job_log.processed_count` に記録する。

**更新対象**：`wf_task.reminder_count`、`wf_timeout_record`、`sys_notification`。

### 4.2 BAT-WF-002 エスカレーション・自動承認

1. `escalate_hours` を経過し `record_type=2` がないタスクを取得する。
2. エスカレーション先を解決（直属上長／ロール／部門長）。上位者へ `WF_TASK_ESCALATED` を通知し、動的代理承認権を付与する。`wf_timeout_record` に記録する。
3. 自動承認が有効な場合、`auto_approve_hours` 経過・金額 ≤ 上限・最終ノード以外の条件で `taskService.complete` を実行する。`wf_task_operation` に `operation_type=9`・`operator_id=0`・理由を記録し、`record_type=3` を記録する。申請者・元承認者へ通知する。
4. 財務関連（`process_category=finance`）は自動承認しない。
5. 失敗時は `record_type=3` を記録せず次回再試行する（最大 3 回、以降はアラート）。

### 4.3 BAT-WF-003 代理期限切れ処理

1. `wf_delegation WHERE status=1 AND valid_to < now()` を `status=2` に更新する。
2. 委任者・代理人へ `WF_DELEGATION_EXPIRED` を通知する（`wf_delegation` の `id` をキーに重複通知を防止）。
3. 実行結果をログに記録する。

### 4.4 BAT-WF-004 流程インスタンス整合検査（読み取り専用）

検査項目：
1. Flowable に存在するが `wf_business_process` にないインスタンス（取りこぼし）。
2. `wf_business_process` に存在するが Flowable にないインスタンス（削除済み・不整合）。
3. `wf_task` の `task_status=20` だが Flowable 側タスクが存在しない（完了漏れ）。
4. Flowable 側タスクが存在するが `wf_task` にない（登録漏れ）。
5. 承認中 30 日超のインスタンス（滞留アラート）。
6. 業務域の伝票ステータス（E31/E32 反映後）と `wf_business_process.process_status` の不一致（業務域 API で照会）。

結果は `sys_data_maintenance_log`（maintenance_type=3）に記録し、検出時は運用担当へ通知する。**是正は自動では行わず**、管理画面（F-WF-009）で個別に処理する。

### 4.5 BAT-WF-005 承認効率集計

1. 当日分（`stat_type=1`）と当月分（`stat_type=2`）の提出・承認・却下・撤回件数、平均/最大承認時間、超時件数、滞留件数を集計する。
2. `wf_process_stat` に UPSERT する（`uk_wf_process_stat`）。同日の再実行は上書き（冪等）。
3. 月次は前月分を確定し、PRT-WF-002 を生成して運用担当・経営層へ配信する（設定時）。

### 4.6 BAT-WF-006 完了プロセスアーカイブ（Phase 2）

完了 1 年超の `wf_*` 履歴をアーカイブスキーマへ移管する。Flowable 履歴（`ACT_HI_*`）は Flowable の履歴レベル設定に従い、Phase 1 では削除しない。Phase 2 でアーカイブ方針を確定する（未決 #2）。

## 5. 異常処理（共通）

| 異常 | 検知 | 処理 | 通知 | 再実行 |
|---|---|---|---|---|
| Flowable API 失敗 | 例外 | リトライ 1 回、失敗でログ ERROR | 運用担当 | 可 |
| 対象データ不整合 | 整合検査 | 処理中断・記録 | 運用担当 | 修正後可 |
| 通知送信失敗 | 通知基盤 | 業務は成功、再送キュー | — | 可 |
| 多重起動 | 実行中ログ | スキップ | なし | 不要 |
| タイムアウト（バッチ） | 監視 | 中断・失敗記録 | 運用担当 | 可 |
