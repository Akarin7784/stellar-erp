## 5. バッチ詳細

### 5.1 `BAT-INV-001` 库存月结

| 項目 | 内容 |
|---|---|
| バッチ名 | 库存月结（在庫月次締め） |
| 実行方式 | 月次スケジュール or 手動（ウィザード） |
| 実行時刻 | 月初第 1 営業日 02:00（[90-data/demo-company.md](../90-data/demo-company.md) §4.2 の月結 1〜5 日） |
| 対象データ | 対象期間の `inv_stock_txn`・`inv_stock_balance`・`inv_cost_layer`・`inv_stocktake`・`inv_cost_adjustment` |
| 冪等性 | `inv_period.period_status=40` なら「実行済み」で正常終了 |
| 排他 | `pg_advisory_lock(hashtext('inv_close:'||company_id||':'||period_code))` |
| 失敗時 | リトライ 1 回（5 分後）。通知：財務经理・倉庫主管・システム管理者 |
| 関連機能 | F-INV-020 |

**処理手順**

1. 起動条件チェック：対象期間が `20 OPEN`、前月が `40/90`、Advisory Lock 取得。
2. 前置检查 11 項目（[06](06-reservation-barcode-close.md) 2.6）を実行。1 項目でも 0 件でなければ `check_result` を保存して中断（通知）。
3. 收发存汇总を生成：対象期間×倉庫×物料で `opening/in/out/closing` を算出し、`inv_stock_summary` を DELETE → INSERT（期間単位）。
4. 検証：数量は `closing = opening + in − out`（DB CHECK でも保証）、金額は丸め誤差 ±0.01 以内を確認。差異があれば中断。
5. 期末平均単価を確定（cost group 単位、6 桁）。
6. `inv_period` を `40 CLOSED` に更新（`closed_at/by`、`check_result`、`summary_count`）。
7. E20 `inventory.period.closed` を Outbox に記録。
8. 翌月期間を `20 OPEN` に更新（未作成なら作成）。
9. 帳票生成（PRT-INV-016/009/012）を非同期で起動。
10. `sys_job_execution` に実行結果を記録し、通知を送信。

**入出力**

| 種別 | 対象 | 内容 |
|---|---|---|
| 入力 | `inv_stock_txn(_line)`、`inv_stock_balance`、`inv_cost_layer`、`inv_stocktake`、`inv_cost_adjustment` | 期間内の確定データ |
| 出力 | `inv_stock_summary`、`inv_period`、`sys_outbox_event`（E20）、帳票 3 種 | 集計・状態・イベント |

**異常処理**

| 異常 | 検知 | 処理 | 通知 | 再実行 |
|---|---|---|---|---|
| 前置检查 NG | 11 項目チェック | 中断（期間状態不変） | 財務・倉庫主管 | 是正後再実行 |
| 収发存不一致 | 検証 | 中断 | 財務・管理者 | 差異調査後 |
| 対象期間が既に关账 | 状態チェック | 実行済みとして正常終了 | なし | — |
| DB エラー | 例外 | ロールバック、リトライ 1 回 | 管理者 | 可 |
| FIN 期間已关账 | `fin_period` 参照 | 中断（順序エラー） | 財務 | FIN と調整 |

### 5.2 `BAT-INV-002` 库存日次对账

| 項目 | 内容 |
|---|---|
| バッチ名 | 在庫日次対账 |
| 実行方式 | 日次 |
| 実行時刻 | 毎日 03:00 |
| 対象データ | 前日までの `inv_stock_balance`・`inv_stock_txn_line`・`inv_cost_layer` |
| 冪等性 | 再実行可（読取 + アラート） |
| 排他 | なし（読取のみ。Advisory Lock で多重起動防止） |

**処理手順**

1. 残高数量と事務明細の累計を比較（IV-01/02、[90](90-db-design.md) 6.1）。
2. 残高金額と成本層残額を比較（IV-03）。
3. 予約数量と有効予約残の比較（IV-04）。
4. 平均単価の一貫性（IV-06）、調撥の金額保存則（IV-07）、状態変換の対（IV-10）を検証。
5. 差異があれば `sys_alert`（RPT 域のアラート）とメールで通知し、月结の中断候補として記録。
6. 検証結果（対象件数・差異件数・実行時間）を保存。

**異常処理**：差異は自動修正**しない**（原因調査を優先）。運用は「差異一覧の出力 → 原因特定 → 手動修正（管理権限 + 監査ログ）」。

### 5.3 `BAT-INV-003` 库龄快照计算

| 項目 | 内容 |
|---|---|
| 実行方式 | 日次（毎日 03:30） |
| 入力 | `inv_cost_layer`（`remaining_qty > 0`）、`inv_stock_txn_line`（出庫実績） |
| 出力 | `inv_age_snapshot`（当日分を洗替） |
| 冪等性 | 再実行可（`snapshot_date` 単位で DELETE → INSERT） |
| 異常時 | 残高との不一致はアラート（`MSG-INV-046`）。バッチは継続（部分成功を許容） |

**処理手順**：[07](07-reports.md) PRC-INV-015-01。層の `received_date` から `age_days`・`age_bucket` を算出し、呆滞判定（365 日超かつ 180 日出庫なし）を付与する。

### 5.4 `BAT-INV-004` 安全库存・补货建议生成

| 項目 | 内容 |
|---|---|
| 実行方式 | 日次（毎日 04:00） |
| 入力 | `mdm_material`（安全在庫・LT・MOQ）、`inv_stock_balance`、`inv_stock_txn_line`（90 日出庫）、PUR の発注残（参照） |
| 出力 | `inv_replenishment`（`10 建議` を洗替） |
| 冪等性 | 再実行可（`as_of_date` + `10 建議` のみ洗替） |
| 異常時 | マスタ未設定はスキップ + 警告ログ（`MSG-INV-016`） |

**処理手順**：[07](07-reports.md) PRC-INV-016-01。ROP（CALC-10）と推奨発注量（CALC-11）を算出し、MOQ/ロット倍数で切上げる。

### 5.5 `BAT-INV-005` 批次效期预警

| 項目 | 内容 |
|---|---|
| 実行方式 | 日次（毎日 04:30） |
| 入力 | `inv_batch`（`expiry_date` あり、`batch_status=10`）、`inv_stock_balance` |
| 出力 | 通知（站内 + メール）、`SCR-INV-017` 用データ |
| 冪等性 | 再実行可（通知キー = `date + batch_id + 区分` で重複抑止） |
| 異常時 | 通知失敗はリトライ（業務データは変更しない） |

**処理手順**：[04](04-batch-serial-status.md) PRC-INV-011-04。期限切れ・期限間近（既定 30 日）を抽出し、在庫 0 は除外する。

### 5.6 `BAT-INV-006` 预留过期自动释放

| 項目 | 内容 |
|---|---|
| 実行方式 | 時次（毎時 00 分） |
| 入力 | `inv_reservation`（`reservation_status IN (10,20,35)`、`expire_date < 当日`） |
| 出力 | 予約解放、`inv_stock_balance.qty_reserved` 減算、E09（RELEASED） |
| 冪等性 | 再実行可（解放済みは対象外） |
| 排他 | 予約行 `FOR UPDATE SKIP LOCKED`（多重起動・他処理との競合を許容） |
| 異常時 | 1 件失敗しても他は継続。失敗一覧を保存・通知 |

**処理手順**：[06](06-reservation-barcode-close.md) PRC-INV-019-06。1 バッチ 1,000 件まで。

### 5.7 `BAT-INV-007` 事件补偿・差异检测

| 項目 | 内容 |
|---|---|
| 実行方式 | 日次（毎日 05:00） |
| 目的 | イベント駆動の在庫更新が失敗・未処理のまま残った場合の検出と再処理（[09 §10.2](../00-common/09-cross-domain-flow.md) の補償） |
| 冪等性 | 再実行可 |

**チェック項目**

| # | チェック | 検出条件 | 処理 |
|---|---|---|---|
| 1 | 未処理 Outbox | INV 関連 `sys_outbox_event.status IN (0,2,9)` | 再送（デッドレターはアラート） |
| 2 | 来源確定・在庫未過账 | E14/E10/E22/E24/E25/E26 受信済だが `inv_stock_txn` が無い | ハンドラ再実行（冪等） |
| 3 | 工单完了・未入庫 | `prd_work_order` 完了で `FGI` 未過账 | 倉庫・PRD へ通知 |
| 4 | 出荷済・未出庫 | SAL の出荷確定（E10）で `SI` 未過账 | ハンドラ再実行 + 通知 |
| 5 | 在庫取引・未仕訳 | E18 発行済で FIN の仕訳が無い（FIN 側チェックと連携） | FIN へ再送 |
| 6 | 予約未処理 | 受注承認済（E06）で予約が無い | 引当再実行 |
| 7 | 品質イベント保留の未適用 | `inv_event_wait.wait_status=0` が 24 時間以上 | E14/E24 の未処理を解消し、E15 を再適用（`MSG-INV-064` アラート） |

**異常時**：恒久失敗はアラート（メール）と運用画面（`sys_job_execution`）に記録。自動修正は行わず、再実行または手動対応を促す。

## 6. スケジュール・監視

| バッチ | スケジュール | 依存関係 | 失敗時の連鎖 |
|---|---|---|---|
| `BAT-INV-002` 日次対账 | 03:00 | 前日までの入出庫が完了していること | 月结（001）の前置检查 #6 に影響 |
| `BAT-INV-003` 庫齢 | 03:30 | 002 の後（残高整合が前提） | 庫齢帳票が前日値になる |
| `BAT-INV-004` 補貨 | 04:00 | MDM マスタ・PUR 発注残が参照可能 | 建議が前日値 |
| `BAT-INV-005` 效期 | 04:30 | なし | 通知遅延 |
| `BAT-INV-006` 予約解放 | 毎時 | なし | 予約が滞留 |
| `BAT-INV-007` 補償 | 05:00 | 002〜006 の完了後 | 月结前置检查 #3 に影響 |
| `BAT-INV-001` 月結 | 月初 02:00 | 002〜007 が正常完了していること | FIN の期間关账が遅延 |
| `BAT-INV-008` 回転率 | 月結後 | 001 の完了後 | 帳票が前月値のまま |

**監視**：`sys_job_execution` に実行履歴（開始・終了・件数・エラー件数）を記録し、SYS の定时任务监控（F-SYS-016）で可視化する。失敗はメール + 站内通知（[08 §13.3](../00-common/08-common-business-rules.md)）。
