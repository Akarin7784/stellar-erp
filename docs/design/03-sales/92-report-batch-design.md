## B.2 バッチ詳細

### B.2.1 BAT-SAL-001 报价单有效期到期处理

| 項目 | 内容 |
|---|---|
| 実行方式 | 日次（スケジューラ） |
| 実行時刻 | 01:00（Asia/Shanghai） |
| 想定処理時間 | 1 分以內 |
| 対象データ | `sal_quotation`（`quotation_status=30`）・`sal_special_price`（`status=25`） |
| 冪等性 | 再実行可（既に 90/40 のものは対象外） |
| 排他 | ジョブ多重起動防止（`sys_job_lock`） |
| 失敗時 | 3 回リトライ、最終失敗でシステム管理者へメール通知 |

**処理手順**
1. 前回実行結果と現在時刻を確認し、二重起動を防止する。
2. `valid_to < 當日` かつ `quotation_status=30` の見積を抽出し、`quotation_status=90`（失効）、`invalidated_at` を更新する。
3. 有効期限 7 日前の見積を抽出し、営業擔當へ站内通知する（當日通知済みは除外）。
4. `sal_special_price` で `status=25` かつ `valid_to < 當日` の行を `status=40`（適用終了）に更新し、営業へ通知する。
5. 実行件數（失効件數・通知件數）を `sys_job_log` に記錄する。

**入出力**

| 種別 | 対象 | 內容 |
|---|---|---|
| 入力 | `sal_quotation` / `sal_special_price` | 有効期限・狀態 |
| 出力 | 同上 + `sys_notification` / `sys_job_log` | 狀態更新・通知・履歴 |

**異常処理**

| 異常 | 検知 | 処理 | 通知 | 再実行 |
|---|---|---|---|---|
| 狀態不整合（null 等） | 件數チェック | 該當行をスキップしログ | 運用 | 修正後再実行 |
| DB 接続エラー | 例外 | ロールバック・リトライ | 管理者 | 可 |

### B.2.2 BAT-SAL-002 受注引当不足再引当

| 項目 | 内容 |
|---|---|
| 実行方式 | 日次 |
| 実行時刻 | 02:00 |
| 対象データ | `sal_sales_order`（`order_status IN (25,30)`）で `reserved_qty + shortage_qty < ordered_qty` の明細 |
| 冪等性 | 再実行可（E06 再通知キーで管理） |
| 関連機能 | F-SAL-003/010 |

**処理手順**
1. 引當不足の受注明細を抽出する（引當なし・一部引當を含む）。
2. INV へ E06 再通知（`eventType=sales.order.approved`、`eventVersion=1`、`payload.retryReason=BACKORDER`）を Outbox に INSERT する。再通知キーは `orderId + versionNo + retryDate` とし、同日重複を防止する。
3. INV から E09 を受信すると通常の引當結果反映（PRC-SAL-002-06）が行われる。
4. 再通知件數・充足件數を `sys_job_log` に記錄し、不足が継続する明細を営業・計画へ通知する。

**異常処理**：INV 側で引當できない場合は `shortage_qty` を保持し、翌日再実行する。E06 の二重通知は Outbox 冪等キーで防止する。

### B.2.3 BAT-SAL-003 交期迟延检出与通知

| 項目 | 内容 |
|---|---|
| 実行方式 | 日次 |
| 実行時刻 | 03:00 |
| 対象データ | 狀態 25/30/35・受注殘 > 0 の明細 |
| 冪等性 | 再実行可（當日通知済みキーで重複防止） |
| 関連機能 | F-SAL-012 |

**処理手順**
1. `delivery_date < 當日` かつ受注殘 > 0 の明細を抽出する（CALC-TR-05）。
2. 前日までに通知済みでない（新規遅延）明細を抽出し、擔當営業・計劃へ站内通知する。
3. `shortage_qty > 0` の明細も担当へ通知する。
4. 通知履歴（`orderLineId + notifyDate`）を `sys_notification` に記録し、件数を `sys_job_log` に記録する。

### B.2.4 BAT-SAL-004 与信台帳照合

| 項目 | 内容 |
|---|---|
| 実行方式 | 日次 |
| 実行時刻 | 03:30 |
| 対象データ | FIN 與信台帳（`credit-usage`）・`sal_credit_ledger_snapshot`（投影）・`sal_receivable_snapshot` |
| 冪等性 | 再実行可（ログのみ、金額は変更しない） |

### B.2.5 BAT-SAL-005 销售订单自动关闭

### B.2.6 BAT-SAL-006 客户对账单生成与送付

| 項目 | 内容 |

|---|---|---|---|
| 正常受信（SUCCESS） | 発票登録・E12 発行・申請 30 | `int_api_call_log`・`sal_invoice` | なし |
| 処理中（PROCESSING） | BAT-SAL-012 で再照会（最大 24 時間） | `int_api_call_log` | なし |
| 項目エラー（FAILED） | 申請を 25 に戻し、エラー理由を記錄 | `int_api_call_log`・エラーファイル | 経理・財務責任者 |
| 通信エラー | INT 域でリトライ、最終失敗でアラート | IF ログ | 運用担当 |
| 重複受信 | `requestId`/`invoiceNo` でスキップ（冪等） | IF ログ | なし |

## C.3 IF-SAL-002 発票交付状態同步（Phase 2）

- 数電票の交付・受領状態を日次で取得し、`sal_invoice.delivery_status`/`delivered_at` を更新する。方式・項目は IF-SAL-001 に準じ、INT 域の設計に従う。
- 交付失敗（メール不達等）は経理へ通知し、再交付または別方法での交付を記録する。

## C.4 IF-SAL-003 顧客 EDI 订单接入（Phase 2）

| 項目 | 内容 |
|---|---|
| 方向 | 受信（顧客注文データ → 受注取込） |
| 方式 | CSV/XML（INT 域が受信し、SAL の取込 API へ連携）。ファイル項目は顧客別マッピングで定義 |
| 頻度 | 随時（顧客送信時） |
| 冪等キー | 顧客コード + 顧客注文番號 + 明細行番號 |
| エラー時 | 行単位エラーをエラーファイルに出力し、全件ロールバックまたは部分取込（設定）。取込結果を顧客へ返信 |

## C.5 IF-SAL-004 物流/快递面单接口（Phase 2）

- 出荷確定時に送り状番號を取得し、`sal_delivery_note.carrier_no` に保存する。配送追跡は日次で取得し、`PRT-SAL-004` の再出力・顧客照会に反映する。
- 接続先・認証は INT 域の設計に従う（本設計では項目のみ定義）。

## C.6 IF-SAL-005 輸出報関データ接口（Phase 2）

- 輸出販売の受注（`export_flag=true`）から、通関に必要な項目（Incoterms、仕向國、積出港、HS コード、數量・金額、通貨）を抽出し、ファイル/EDI で報関行へ送信する。項目定義は [07-tracking-reports.md §4.4.3](07-tracking-reports.md) と 90-data の HS コードを正とする。

## C.7 IF-SAL-006 客户对账单电子送付（P1）

| 項目 | 内容 |
|---|---|
| 方向 | 送信（PDF メール/ポータル） |
| 方式 | SMTP（SYS 通知基盤）または顧客ポータル |
| 頻度 | 月次（BAT-SAL-006） |
| 再送 | 可（送付履歴を記錄し、再送時は履歴追加） |
